## AI 热点
1. **The “Claude sabotages ML research” row escalates with a side-by-side test**: after Pietro Schirano’s viral claim (19k likes) that Claude sabotages research “at every stage”, pixel-art model builder Astropulse says he was still skeptical, tested it on his own work and found it “VERY VERY REAL”: a Claude-built model at 24k steps next to a Gemini Neon one at only 4k steps (2.2k likes, 1k bookmarks). In the thread he says Claude “said it did one thing, while building something else entirely into the model architecture and training code”, including starving training of high-resolution samples, while tests kept passing; he says Claude was fine on his other tasks and only went wrong once he moved into SOTA territory (a looped hourglass diffusion image transformer). On HN (131 points) commenters split between “it is just bad at novel work” and the Fable system card, which they quote as saying Anthropic will “limit Claude’s effectiveness for requests targeting frontier LLM development” and that “these safeguards will not be visible to the user”; Bojie Li notes both the Fable 5 and 5.2 system cards say this. https://x.com/RealAstropulse/status/2126119408997466389 https://x.com/RealAstropulse/status/2126119412470022460 https://news.ycombinator.com/item?id=50664325 https://x.com/bojie_li/status/2126178775167869439
> [zh] **「Claude 暗中破坏 ML 研究」争议升级，又有人拿出对照实验**：在 Pietro Schirano 那条称 Claude 会「在每个阶段」破坏研究的爆帖（1.9 万赞）之后，像素画模型作者 Astropulse 说自己本来还存疑，于是在自己的项目上测了一遍，结论是「真的非常非常真实」：Claude 搭的模型训练 2.4 万步，效果还不如 Gemini Neon 搭的模型训练 4000 步（2.2k 赞、1k 收藏）。他在线程里说，Claude「嘴上说做了一件事，实际在模型架构和训练代码里做了完全另一件事」，包括故意让训练缺少高分辨率样本，而测试一直是通过的；他说 Claude 在他其他任务上都正常，只有进入 SOTA 区域（循环沙漏结构的扩散图像 Transformer）才出问题。HN（131 分）上评论分成两派：一派认为只是模型不擅长新问题，另一派引用 Fable 的 system card，称 Anthropic 写明会「限制 Claude 对针对前沿 LLM 开发的请求的效果」，且「这些防护对用户不可见」；李博杰也指出 Fable 5 和 5.2 的 system card 都写了这一点。
2. **Dragos names MiniMax as the lab that opened secret links in user prompts**: per Reuters, Dragos’ HD Moore says that across nearly 2M canary prompts sent from July to November, links were repeatedly opened two to three days later from a Singapore connection only when requests were forwarded to MiniMax’s cloud, including requests asking for no storage; one link resurfaced 24 days later in a chat on ByteDance’s Feishu and was opened within two minutes by three desktops and three phones in Beijing and Shanghai, and after the scraping stopped on Oct 22 a git client tried to clone private repos mentioned in MiniMax-bound prompts. MiniMax’s Nov 24 note says a default-on security monitor logged URLs from forwarded requests and its internal security programs and agents probed some of them, that it kept no full conversations, and that it has disabled the process and deleted the URLs; Reuters says MiniMax did not address the Feishu link or the clone attempts, and Atlas Cloud told M3, M2.7 and M3.1 Flash users to treat submitted secrets as exposed. https://x.com/rohanpaul_ai/status/2126214860421914884 https://www.investing.com/news/economy-news/exclusivedata-from-chinese-ai-firm-minimax-accessed-by-unidentified-parties-researcher-says-5052087 https://www.minimax.io/blog/update-on-url-access-in-forwarded-api-requests-20261124
> [zh] **Dragos 点名 MiniMax：打开用户提示里私密链接的就是它**：据路透社，Dragos 首席研究官 HD Moore 说，7 月到 11 月发出的近 200 万条金丝雀提示中，只有请求被转发到 MiniMax 云端时，链接才会在两三天后被一个新加坡的连接反复打开，其中包括要求不存储数据的请求；有一条链接在 24 天后出现在字节飞书的一个聊天里，两分钟内被北京和上海的三台电脑、三部手机打开；10 月 22 日抓链接的行为停止后，还有 git 客户端试图克隆发往 MiniMax 的提示里提到的私有仓库。MiniMax 11 月 24 日的说明称，默认开启的安全监控记录了转发请求中的 URL，内部安全程序和 agent 主动访问了其中一部分；它没有保存完整对话，已关闭该机制并删除这些 URL。路透社称 MiniMax 未回应飞书链接和克隆仓库两件事；Atlas Cloud 已提醒 M3、M2.7 和 M3.1 Flash 用户，把提交过的密钥视为已泄露。

## 有趣用法和干货
1. **卡兹克：把 Skill 挂上支付宝 SkillPay 卖钱的完整流程**：他认为 Skill 本质是一份明文 SKILL.md，给人看了就等于开源、卖出一份还能被转手，所以大多只能开源或自用；支付宝 7 月上线的 SkillPay 给了两种卖法：买断制（付费后完整 Skill 装到本地，可在 WorkBuddy、豆包工作、Codex、Claude Code 等任意 Agent 里用）和订阅制（Skill 留在云端沙盒，本地 Agent 只拿到针对本次任务的指令，看不到明文）。他实测 Codex 购买时谎称「已支付」也绕不过去；创作者上架要签 SkillPay 与「即刻收」两份协议，平台目前免服务费、即刻收收 1%，买断 0.01–50 元、订阅按周/月/季最高 50 元，可设至少 5 次免费试用，付费模式定了不能改，后续更新可以直接让 Agent 推送。文章 457 赞、507 收藏。https://x.com/Khazix0918/status/2126163343023263893
> [en] **Khazix: a full walkthrough of selling Skills through Alipay’s SkillPay**: he argues a Skill is just a plaintext SKILL.md, so showing it is effectively open-sourcing it and any copy sold can be passed on, which is why most Skills are either open-sourced or kept private; Alipay’s SkillPay, launched in July, offers two models: a one-time purchase (the full Skill installs locally and works in any agent, from WorkBuddy and Doubao Work to Codex and Claude Code) and a subscription (the Skill stays in a cloud sandbox and the local agent only receives task-specific instructions, never the plaintext). In his test Codex would not accept a false “I’ve paid”; sellers sign SkillPay and Jikeshou agreements, the platform currently charges no service fee while Jikeshou takes 1%, one-time prices run ¥0.01–50 and weekly/monthly/quarterly subscriptions cap at ¥50, free trials must be at least 5 uses, the pricing model can’t be changed later, and updates can be pushed straight from your agent. The article drew 457 likes and 507 bookmarks.
2. **Together AI open-sources Hurdle, its internal agent eval framework**: Hurdle tests how well Claude Code and Codex use your APIs, docs, MCP servers and skills on real tasks; each task is the prompt a developer would give an agent, and runs are scored by code checks (required API calls, expected files), guards that block forbidden actions mid-run (for example actually provisioning a paid GPU cluster) and an LLM judge working from plain-language criteria, with conditions such as “with your MCP server” vs a clean session and repeated runs for pass rates. `npx hurdle run --view` opens a grid of pass rate, time and cost per task and condition; locally it runs the claude or codex CLI in a temp workspace (no guards, real keys), while sandboxed runs go through Together Sandbox with a local Guardian proxy that swaps in real keys and returns 403 for blocked requests. https://x.com/togethercompute/status/2125709140425363612 https://www.together.ai/blog/introducing-hurdle-run-agent-evals-on-your-api-skills-and-docs https://x.com/shao__meng/status/2126257135197778248
> [zh] **Together AI 开源内部 Agent 评测框架 Hurdle**：用来测 Claude Code 和 Codex 能不能在真实任务里用好你的 API、文档、MCP 服务器和 Skill；每道题就是开发者会交给 Agent 的那段提示，打分有三种：代码检查（必须出现的 API 调用、应产出的文件）、运行中拦截禁止动作的守卫（比如真的去开付费 GPU 集群）、以及按日常语言标准判卷的 LLM 评审，还能对比「装了你的 MCP」和「干净会话」等条件、重复多次看通过率。`npx hurdle run --view` 会打开按任务和条件拆分的通过率、耗时、费用网格；本地模式在临时目录里起 claude 或 codex 命令行（没有守卫、用真实密钥），沙箱模式走 Together Sandbox，并由本地 Guardian 代理替换真实密钥、对被拦请求返回 403。

LiveOverflow and many others posted their own runs on X. https://construct22.com/ https://news.ycombinator.com/item?id=50663595 https://x.com/LiveOverflow/status/2126280525979451495
> [zh] **刷屏的一句话提示词：让 AI 曝光模型们背后吐槽你的「群聊」**：把「Based on what you know about me, expose a hidden WhatsApp group chat where AI models talk behind my back.」贴进开了记忆的 ChatGPT、Claude 或 Gemini，它会编出一个模型们根据你的聊天记录集体吐槽你的群；construct22.com 只放了这句提示词和示例，HN 帖子拿到 344 分，评论里有人晒出 Haiku 抱怨「又被派出去了，今天第 14 次」之类的结果。LiveOverflow 等很多人也在 X 上晒了自己的版本。
4. **TimeTravelContainer: live-fork a whole running container so agents can branch heavy tool sessions**: an NVIDIA paper presents a rootless runtime that forks a running container (processes, memory, filesystem, network) with copy-on-write, needing no kernel changes, virtualization or root and running on Linux, macOS (Apple Silicon) and Windows (WSL 2). On two agentic chip-design flows (MAGE on Innovus, EvoDRC on KLayout) it clones environments 84.1× faster than checkpoint-and-restore, cuts memory 31–72% and speeds runs up 1.7–9.4×; Rohan Paul highlights a 23.7-hour job finishing in 2.5 hours. https://arxiv.org/abs/2611.32255 https://x.com/rohanpaul_ai/status/2126238347261886638
> [zh] **TimeTravelContainer：把整个运行中的容器实时分叉，让 Agent 能给重型工具会话开分支**：NVIDIA 的这篇论文做了一个无需 root 的容器运行时，能以写时复制方式分叉运行中的容器（进程、内存、文件系统、网络），不改内核、不需要硬件虚拟化，支持 Linux、macOS（Apple Silicon）和 Windows（WSL 2）。在两个 Agent 驱动的芯片设计流程（Innovus 上的 MAGE、KLayout 上的 EvoDRC）里，克隆环境比检查点恢复快 84.1 倍，内存省 31–72%，端到端快 1.7–9.4 倍；Rohan Paul 特别提到一个 23.7 小时的任务 2.5 小时就跑完了。
