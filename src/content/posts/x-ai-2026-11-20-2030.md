2. **GPT-6.2 Astra tops Blueprint-Bench 2, a test of drawing floorplans from apartment photos**: On the normalized room-connectivity metric, [Andon Labs’ leaderboard and methodology](https://andonlabs.com/evals/blueprint-bench-2) listed GPT-6.2 Astra first at 0.614, Gemini 4 Carbon and the human baseline at 0.586, and GPT-6.2 Sol at 0.570 (third among models, fourth including the human baseline). Each agent processed 50 apartments in sequence with a persistent notepad; the human baseline covered only a 12-apartment subset. Greg Brockman highlighted Astra’s result, but the published scores do not establish general superiority over humans at spatial reasoning. Separately, dotey reported that Sol handled simpler coding tasks in their own testing but needed Opus 5.5 to clean up some harder work; that is an individual account, not part of the benchmark. ## 有趣用法和干货
1. **宝玉：自动化别教 Agent 每一步，用「目标 → 验收 → 改进」循环让它自己进化**：针对 Lauren Tan 的自动化入门指南（先讲清目标、再把自己的做法教给 bot），宝玉更强调目标和验收：先告诉 AI 要什么，再给验收标准和验收工具（截图、检索、代码运行环境），例如新闻自动化要求动笔前必须做事实核查；然后先跑一遍再调，「调整结果才是最考验专业水准的地方」；最后让它自我进化：把打磨好的做法趁热沉淀成 Skill，每轮执行后往 lessons.md 记教训、再由模型决定是否改 Skill，Skill 变臃肿就定期让 Agent 重构，并重跑原有测试集。https://x.com/dotey/status/2123667995570413718
> [en] **dotey: don’t teach an agent every step; let it evolve through a goal → acceptance → improvement loop**: responding to Lauren Tan’s automation primer (state the goal, then teach the bot how you do it), dotey puts the weight on goals and acceptance: say what you want, then give acceptance criteria plus tools to check them (screenshots, search, a code runtime), e.g. his news automation must fact-check before writing; run it once and then adjust, since “adjusting the result is where expertise is really tested”; finally let it evolve: turn a polished run into a Skill while it’s fresh, log lessons to lessons.md after each run and let the model decide whether to update the Skill, have the agent refactor bloated Skills periodically, and rerun the existing test sets afterwards.
2. **铁锤人：把 App Store 和 Google Play 的拒审坑做成 Skill + 预审 Hook**：开源项目 app-store-compliance 整理了 117 种有记录的拒审模式和修复办法，外加隐私清单与 Data safety 检查、95 个合规截止日期（欧盟 AI 法案、DSA、COPPA、年龄法规等）；两条命令即可扫描项目，install.sh 能装进 Claude Code、Codex、Gemini CLI、Cursor、Copilot 等工具，在提交前标出缺 PrivacyInfo.xcprivacy、有登录却没有 App 内删号入口、把用户数据发给外部 AI 却没弹授权等问题并给出文件和行号。今天在 GitHub Trending 新增约 380 星。https://x.com/lxfater/status/2123625468729413925 [GitHub](https://github.com/mjmirza/app-store-compliance)
> [en] **lxfater: App Store and Google Play rejection traps packaged as a Skill plus a pre-submission hook**: the open-source app-store-compliance collects 117 documented rejection patterns with fixes, privacy-manifest and Data safety checks, and 95 tracked compliance deadlines (EU AI Act, DSA, COPPA, age laws); two commands scan a project, and install.sh wires it into Claude Code, Codex, Gemini CLI, Cursor, Copilot and more, flagging issues before submission, such as a missing PrivacyInfo.xcprivacy, sign-in without in-app account deletion, or sending user data to an outside AI without a consent prompt, with file and line numbers. It gained about 380 stars on GitHub Trending today.
3. **CSPD: stack RL skills onto a frozen LLM as 256-token soft prompts**: former ByteDance Seed RL researcher Zhen Zhang and collaborators distill each RL expert into a 256-token soft prompt (~0.01% of parameters) that is simply prepended; across 23 teacher–student pairs on math, code and agents, average recovery of the RL gain exceeds 100%. Prompts compose by stacking with no joint training: math + code + science + instruction-following reach 67.7 average, above the individual experts (66.6) and on par with MOPD (67.8), with almost no forgetting; on six out-of-distribution benchmarks scores rise from 50.3 to 56.6, and serving a different soft prompt per request on GPT-OSS-20B keeps throughput within 1.5% of the bare model. https://x.com/Chinazhidx/status/2123634944085995909 [作者线程](https://x.com/zhenzhangzz/status/2123215871434964998)
> [zh] **CSPD：把强化学习练出的技能做成 256 token 软提示，叠加到冻结的大模型上**：前字节 Seed RL 研究员 Zhen Zhang 等人把每个 RL 专家蒸馏成一段 256 token 的软提示（约占参数的 0.01%），推理时直接拼在输入前；在数学、代码、Agent 的 23 组师生配对上，平均恢复的 RL 增益超过 100%。软提示直接叠加即可组合、无需联合训练：数学 + 代码 + 科学 + 指令遵循合起来平均 67.7，高于各单项专家（66.6），与 MOPD（67.8）持平，几乎不遗忘；6 个分布外基准从 50.3 升到 56.6；在 GPT-OSS-20B 上每个请求换不同软提示，吞吐与裸模型相差不到 1.5%。

> [en] **Khazix: 13 useful plugins at DeepSeek Harness’s 100-day mark**: a long post on DSH’s 100th day: 284k GitHub stars and about 35k third-party plugins; start with the dshmarket plugin store (nearly 12k plugins from awesome-dsh-plugin, each page showing that day’s dsh-trust-check scan that flags plugins able to read keys or call models, a guard against malicious plugins); an official experimental plugin imports conversations exported from DeepSeek’s web app; dsh-context and dsh-cost-meter together show context composition and the cost of each turn and sub-agent; billion-context compresses history in long tasks into recoverable summaries (one 10-sub-agent research run compressed 48 times, shrinking one sub-agent’s 350k-token history to 13k); and dsh-pocket lets you assign work to the desktop DSH from your phone.
