2. **Google Antigravity ships Dynamic Workflows (`/run-workflow`)**: the official account said you can use /run-workflow and the agent writes a Python script to orchestrate parallel and sequential subagents with structured handoffs, so you get deterministic control flow instead of prompt drift; you review the script before it runs and can save it to rerun the same flow. It is available on Google AI Pro and Ultra, in the Antigravity app and CLI. The agent reads a built-in `run-workflow` skill, writes a short Python script, and unless a permission preset such as Turbo already allows it, asks you to approve the script before it runs in the background. Scripts use `parallel()` and `pipeline()` in named phases; each spawned agent has its own conversation and returns a JSON-Schema result, keeping file reads and test logs out of the main thread. Antigravity ships its own Python for workflows (unpacked on first run; override with `ANTIGRAVITY_PYTHON` for Python 3.8+). Docs distinguish this from Orchestrator, subagents, `/swarm`, `/boost` and `/teamwork`. https://x.com/antigravity/status/2121327669534933025 | https://antigravity.google/docs/dynamic-workflows/
> [zh] **Google Antigravity 上线 Dynamic Workflows（`/run-workflow`）**：官方账号说，使用 /run-workflow 后，Agent 会写一段 Python 脚本来编排并行和串行的子 Agent，并用结构化交接，从而得到确定的控制流，而不是提示词漂移；脚本运行前你可以审阅，也可以存下来重复跑同一套流程。Google AI Pro 和 Ultra 可用，Antigravity 应用和 CLI 都支持。Agent 会读取内置的 `run-workflow` skill，写出一小段 Python 脚本；除非 Turbo 这类权限预设已经允许，否则会在后台运行前先请你批准。脚本按命名阶段使用 `parallel()` 和 `pipeline()`；每个拉起的 Agent 有自己的对话，并返回符合 JSON Schema 的结果，文件读取和测试日志不会涌进主线程。Antigravity 自带一份工作流用的 Python（首次运行时解包；也可用 `ANTIGRAVITY_PYTHON` 指定 3.8+ 的环境）。文档把它和 Orchestrator、子 Agent、`/swarm`、`/boost`、`/teamwork` 区分开来。

1. **花叔对照 Anthropic 常驻 Agent 和 DeepSeek Super-agent，当天在 FanBox 2.20.0 里落地**：他读了 DeepSeek Harness 10 月 31 日的 Super-agent 设计长文，以及 Anthropic 13 日的《Building always-on agents》（今早汇总已介绍），在开源项目 FanBox 里做了一个版本，随 2.20.0 发布。用法是：终端里的 Agent 停下来等人时，如果你不在电脑前，微信或飞书会收到一句提醒，Agent 就能少打断地昼夜接着干。文章把 Anthropic 的五个部件对到 FanBox 上，并转述了 DeepSeek 五个模块和初步实验数据（Super-agent 中位耗时 12.4 分钟，对单会话基线 29.5 分钟；缓存读取 token 为 23.23M 对 6.05M，原文标明是合成流量、仅初步结果）。第 6 节还写了四条不必用 FanBox 也能借鉴的实现坑。https://x.com/AlchainHust/status/2121485281744531496 | https://x.com/i/article/2121484176033751040 | https://github.com/alchaincyf/fanbox
> [en] **花叔 mapped Anthropic's always-on agents and DeepSeek's Super-agent into FanBox 2.20.0 the same day**: he read DeepSeek Harness's Super-agent design essay (31 Oct) and Anthropic's 13 Nov "Building always-on agents" (already in this morning's digest), implemented a version in the open-source FanBox project, and shipped it in 2.20.0. The idea: when the terminal agent stops and waits and you are not at the computer, WeChat or Feishu gets a one-line message, so the agent can keep working around the clock with less context-switching. The article maps Anthropic's five primitives onto FanBox, and restates DeepSeek's five modules plus preliminary experiment numbers (Super-agent median 12.4 min vs 29.5 min for a single-session baseline; cache-read tokens 23.23M vs 6.05M, marked as synthetic traffic and preliminary only). Section 6 describes four implementation pitfalls that can be reused without FanBox.

3. **TurboFieldfare：在 8 GB 的苹果芯片 Mac 上用约 2 GB 内存跑 Gemma 4 26B**：这是 Andrey Mikhaylov 写的 Apache 2.0 运行时，用 Swift + Metal 为 Gemma 4 26B-A4B IT（每 token 约 3.88B 激活参数）定制，不是套 MLX 或 llama.cpp。它把约 1.35 GB 的共享核心和 FP16 KV cache 留在内存里，按需从 SSD 流式读取被路由到的专家，权重加 4K KV cache 大约只占 2 GB 内存。作者实测：8 GB 的 M2 MacBook Air 解码 5.1–6.3 token/s，24 GB 的 M5 Pro 为 31–35 token/s；需要 macOS 26、Metal 4、Swift 6.2+，模型下载约 14.3 GB 文本（另有约 1.1 GB 可选图像包）。提供原生 Mac 聊天应用、命令行，以及实验性的本机 OpenAI 兼容服务，与 Google 无关，权重需自行从指定的 Hugging Face 节点下载。https://x.com/GitHub_Daily/status/2121475738759225556 | https://github.com/drumih/turbo-fieldfare
> [en] **TurboFieldfare: run Gemma 4 26B in about 2 GB of memory on an 8 GB Apple-silicon Mac**: this Apache 2.0 runtime by Andrey Mikhaylov is a custom Swift + Metal stack for Gemma 4 26B-A4B IT (~3.88B active parameters per token), not a wrapper around MLX or llama.cpp. It keeps a 1.35 GB shared core plus an FP16 KV cache in memory and streams routed experts from SSD; weights plus a 4K KV cache take about 2 GB of RAM. The author measured 5.1–6.3 tok/s decode on an 8 GB M2 MacBook Air and 31–35 tok/s on a 24 GB M5 Pro; it needs macOS 26, Metal 4 and Swift 6.2+, and the model download is about 14.3 GB of text (plus an optional ~1.1 GB image pack). It ships a native Mac chat app, a CLI, and an experimental loopback OpenAI-compatible server. It is independent of Google; weights are downloaded separately from a pinned Hugging Face checkpoint.
