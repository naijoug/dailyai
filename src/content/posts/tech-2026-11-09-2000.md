## 科技新闻
1. **Backfill: @GitHub in Slack and Teams reaches general availability**: GitHub’s November 6 changelog says conversations can initiate bug investigations, issues, implementations and pull requests. Teams Canvas adds shared review of plans, code and previews; generated issues and PRs identify the originating conversation and user. This is an integration availability update, not permission to modify every repository. Check app access and repository scope before delegating changes. https://github.blog/changelog/2026-11-06-github-copilot-in-slack-and-teams-is-generally-available/
> [zh] **补漏：Slack 与 Teams 中的 @GitHub 正式开放**：GitHub 11 月 6 日日志说明，可从聊天发起问题调查、创建 issue、实现修改并打开 PR。Teams Canvas 支持共同查看计划、代码和预览；生成的 issue 与 PR 会注明来源会话及用户。这是集成可用性的更新，不代表拥有所有仓库的修改权限；委派改动前仍应核对应用访问权限与仓库范围。

## 有趣用法和干货
1. **Make agent-written PRs easier to review without discarding the evidence**: Simon Willison’s November 9 workflow puts a short, human-curated introduction first and folds the longer agent explanation into GitHub-supported `details`/`summary` markup, labelled with the model. This is his editorial practice, not a new GitHub feature or proof that generated descriptions are correct. Editorial takeaway: keep decisions and test evidence available, but make the first screen worth a reviewer’s time. https://simonwillison.net/2026/Nov/9/details-summary/
> [zh] **让 Agent PR 更易审阅，而不丢掉证据**：Simon Willison 在 11 月 9 日介绍的做法是，先放一段经过人工精选的简短介绍，再用 GitHub 支持的 `details`/`summary` 标签折叠 Agent 的长说明，并标注模型。这是个人编辑实践，不是 GitHub 新功能，也不能证明生成说明正确。编辑总结：保留决策与测试证据，但让读者第一屏就看明白值得关注的内容。
