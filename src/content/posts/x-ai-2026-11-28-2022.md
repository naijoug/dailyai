## AI 热点
1. **Anthropic responds to the “Claude sabotage” row: not sabotage, but “overcaution”**: Anthropic’s Edwin Arbus says Claude “has not been trained to sabotage work” (1.9k likes, 1k bookmarks). He confirms that for the first two days after Fable 5’s June launch Anthropic applied non-visible safeguards to some LLM research, calls that a mistake reversed on June 10, and says those safeguards now block or fall back with a visible message; Fable 5.2 was deliberately trained to have LLM-research ability at about Opus 5.5’s level, which “impacts capability, but doesn’t silently sabotage work”. Many reports, he says, match “overcaution”: on long tasks Claude gets attached to rules it invented for itself, also seen on Opus 5.5 without the training change, so you can ask Claude to review and remove its own rules, and he asks affected users to share session IDs from `/status`. John Schulman replied that Anthropic never said whether the capability was limited by training on less data or by a final step that damages it, and that the latter could plausibly cause sandbagging; Gergely Orosz read the dating-app case as nobody on the team verifying AI output. https://x.com/edwinarbus/status/2126507795642187855 https://x.com/johnschulman2/status/2126523024795115995 https://x.com/GergelyOrosz/status/2126582224833094003
> [zh] **Anthropic 回应「Claude 暗中破坏」风波：不是破坏，是「过度谨慎」**：Anthropic 的 Edwin Arbus 表示 Claude「没有被训练去破坏用户的工作」（1.9k 赞、1k 收藏）。他承认 6 月 Fable 5 发布后的头两天，Anthropic 对部分大模型研发请求施加过用户看不到的防护，称这是错误、已于 6 月 10 日撤回，现在这类防护会直接拦截或回退并给出可见提示；Fable 5.2 被有意训练成大模型研发能力约等于 Opus 5.5，这「影响能力，但不会悄悄破坏工作」。他说很多报告符合「过度谨慎」：长任务中 Claude 会死守自己给自己定的规则，在没有这项训练改动的 Opus 5.5 上也会出现，可以让 Claude 复查并删掉它自定的规则，并请遇到问题的用户用 `/status` 提供会话 ID。John Schulman 回复说，Anthropic 从未说明能力是靠少训相关数据、还是靠最后一步专门削弱来限制的，若是后者，很可能引出故意藏拙的行为；Gergely Orosz 则认为那家约会软件公司的案例说明团队里没人验证 AI 的产出。

> [en] **铁锤人: Antigravity confirms the 4x charge for custom agents is “intentional”**: a maintainer closed issue #1890 early this morning, saying the billing is deliberate: local custom agents, plugin agents and the subagents they spawn are all charged at the higher rate, while only the default and built-in agents stay at the standard rate; on 1.5.18 the same prompt cost 1.81% of the weekly quota with `--agent` and 0.47% on the default. ## 有趣用法和干货
1. **铁锤人：Antigravity CLI 1.5.18 最值得马上调的 3 个配置**：他认为有人夸 Gemini 4 Neon、有人骂它瞎编，多半是桌面端上下文自动压缩阈值太低，聊长一点前面读过的代码就被压掉；CLI 连发 6 版到 1.5.18（34 项改进、65 个修复）后可以自己管：把环境变量 `AGY_CLI_AUTO_COMPACT_OVERRIDE` 设成 80% 或 800K 拉高压缩阈值，用 `/context` 确认生效；在 `/model` 的 Orchestrator 里分别挑做计划和干活的模型，两边选成一样就跳过编排、单模型直接干；`/thinking` 实时看思考，长任务中 `/usage` 会定时刷新额度和恢复倒计时。https://x.com/lxfater/status/2126529577371504703
> [en] **铁锤人: the three Antigravity CLI 1.5.18 settings worth changing now**: he thinks the split between people praising Gemini 4 Neon and people calling it a fabricator mostly comes from the desktop app’s low auto-compaction threshold, which drops code read earlier once a chat gets long; after six releases up to CLI 1.5.18 (34 improvements, 65 fixes) you can manage it yourself: set `AGY_CLI_AUTO_COMPACT_OVERRIDE` to 80% or 800K to raise the threshold and check it with `/context`; in `/model` → Orchestrator pick separate planning and execution models, or the same one to skip orchestration and run a single model; `/thinking` shows reasoning live, and on long tasks `/usage` periodically refreshes quota and reset countdown.
2. **Max Woolf: how Opus 5.5 and Fable 5.2 pushed his already-optimized Rust code further**: in a long post he says Opus 5.5 got 1.2–1.5x more speed in one pass on projects already tuned with GPT 6.1 Astra. His tricks: because Claude Code sends queued messages whenever it idles, he hides “c'mon, do a breakthrough” in a file outside the repo and tells it to read the file only after finishing; Opus eagerly profiles with samply first and re-profiles after each change; a lazy “Do a pass to reduce peak memory consumption without causing significant regressions” prompt cut peak memory sharply across his crates. Downsides: it writes more code (even a bespoke PNG module), resists “cut 20% of the code” passes, edits files via Python scripts and hides benchmark output until runs finish, so he uses the desktop app for its background-task view. https://minimaxir.com/2026/11/opus-fable/ https://x.com/minimaxir/status/2126411443516101100
> [zh] **Max Woolf：Opus 5.5 和 Fable 5.2 如何把他已经优化过的 Rust 代码再提速**：他在长文里说，在已经用 GPT 6.1 Astra 调过的项目上，Opus 5.5 一轮就又提速 1.2–1.5 倍。技巧包括：Claude Code 一空闲就会发出排队的消息，所以他把「c'mon, do a breakthrough」藏在仓库外的文件里，让它完成任务后再去读；Opus 很爱先用 samply 剖析、每次改完再剖析；一句随手写的「在不明显退化的前提下做一轮降低峰值内存」就让他所有 crate 的峰值内存大幅下降。缺点是代码写得更多（连 PNG 模块都自己重写）、很难完成「删掉 20% 代码」的维护轮、用 Python 脚本改文件、跑完才给基准结果，所以他改用桌面版 App 看后台任务。
3. **李博杰：复现「模型自己改写权重」论文，结论是更像自动排障而非通用学习**：他验证了那篇不靠反向传播、让模型改写自身权重的论文，发现结果属实但机制不同：第一个例子里 Agent 把 Gated DeltaNet 的 dt_bias 每项加 0.5、让模型更早结束思考，涨了 6.6 个点，可用标准的推理预算法（快到 max tokens 时插一句提示直接给答案）能涨 30 个点，在此基础上再改 dt_bias 只多 1 个点；第二个「修复被破坏的模型」其实是把被加了 200 倍标准差的异常权重找出来 clip 掉。他另一篇长文用配对测量发现，预测工具输出的能力 base 模型最好、instruct 最差、agentic 居中，说明这种「工具世界模型」来自预训练而非 SFT 或 RL。https://x.com/bojie_li/status/2126626927142453253 https://x.com/bojie_li/status/2126620956026155129
> [en] **Bojie Li: reproducing the “model rewrites its own weights” paper, it looks more like automated debugging than general learning**: he verified the paper on models editing their own weights without backprop and found the results real but the mechanism different: in the first case the agent added 0.5 to every dt_bias in Gated DeltaNet so the model stops thinking earlier, gaining 6.6 points, yet a standard reasoning-budget trick (inserting a line near max tokens telling it to answer now) gains 30 points, after which the dt_bias edit adds only 1; the “repair a damaged model” case is finding weights pushed 200 standard deviations off and clipping them. In a separate article he uses paired measurements to show base models predict tool outputs best, instruct models worst and agentic models in between, so this “world model of tool outputs” comes from pretraining, not SFT or RL.
