## AI 热点
1. **Alibaba officially launches Qwen4-Max**: Qwen announced the full release of Qwen4-Max (the preview opened on 11 Nov), a new MoE model with native vision and a 1M-token context window. The official post claims it beats Qwen3.8-Max with up to ~50% fewer tokens and cuts average cost per task by more than 60% in internal evaluation; international pricing is $1.5/M input, $4.5/M output and $0.075/M for implicit caching (caching down 70%). Follow-up posts say token use on its Work360 benchmark (26 Tier-1 domains, 182 subdomains) drops about 24% (Xhigh) and 35% (High), and about 48–49% on Terminal-Bench 4.0, with average cost per Work360 task falling from $4.43 to $1.67. Arena posts put it #6 in Code Arena: WebDev (+74 points over Qwen3.8-Max) and say Alibaba is now the #5 lab overall on Agent Arena. Chinese coverage (IT之家, @Chinazhidx) adds 2.4T total / 71B active parameters, Gated DeltaNet in three of every four layers plus Qwen Sparse Attention, an N-gram Embedding layer, CNY pricing of ¥10/¥30 per M tokens, and an open-sourced Live Delivery plugin that ships a usable first draft and then iterates. The API is live on QwenCloud and the model is in Qwen Studio, QwenWork and Qoder; smaller Qwen4 open-weight models are promised next. The launch post had about 4,000 likes at fetch. https://x.com/Alibaba_Qwen/status/2122148127520289151 | https://qwen.ai/blog?id=qwen4-max | https://www.ithome.com/1/027/512.htm
> [zh] **阿里正式发布 Qwen4-Max**：千问宣布 Qwen4-Max 正式上线（11 月 11 日先开了预览版），新一代 MoE 架构，原生视觉，100 万 token 上下文。官方帖称它比 Qwen3.8-Max 更强，token 最多少用约 50%，内部评测里单任务平均成本降超 60%；国际版价格为输入每百万 1.5 美元、输出 4.5 美元、隐式缓存 0.075 美元（缓存降价 70%）。后续帖子说，在自家 Work360 基准（26 个一级领域、182 个子领域）上，Xhigh 和 High 两档 token 用量分别降约 24% 和 35%，Terminal-Bench 4.0 上降约 48%–49%，Work360 单任务平均成本从 4.43 美元降到 1.67 美元。Arena 方面，它在 Code Arena: WebDev 排第 6（比 Qwen3.8-Max 高 74 分），阿里在 Agent Arena 上升到实验室总榜第 5。中文报道（IT之家、@Chinazhidx）补充：总参数 2.4 万亿、激活 710 亿，每四层里三层用 Gated DeltaNet、一层用 Qwen Sparse Attention，另有 N-gram Embedding 层；人民币价格为每百万输入 10 元、输出 30 元；同步开源 Live Delivery 插件，先交付可用首版再逐版迭代。API 已在 QwenCloud 上线，Qwen Studio、QwenWork 和 Qoder 可用；小尺寸 Qwen4 开放权重模型随后发布。抓取时发布帖约 4,000 赞。
2. **OpenAI launches a science blog; first post: GPT-6 Astra helps define the Standard Model on a lattice**: OpenAI opened a new science blog with a guest post by UCSB particle theorist Nathaniel Craig, now a visiting scientist at OpenAI. He writes that he had a strategy for giving the Standard Model a nonperturbative definition on a spacetime lattice but could not prove it covered every needed case; in an October preprint, GPT-6 Astra “helped turn that strategy into a construction and took the lead in developing the detailed proof.” He frames it as a candidate definition, notes the continuum limit is still open, and points to OpenAI’s recent Yang–Mills existence proof as the missing piece for a simplest unified theory with Standard Model gauge fields and fermions. Greg Brockman shared it as “GPT-6 Astra for theoretical physics.” https://x.com/OpenAI/status/2122123437141553630 | https://openai.com/index/step-toward-defining-the-standard-model
> [zh] **OpenAI 开设科学博客，首篇讲 GPT-6 Astra 协助在格点上定义标准模型**：OpenAI 新开科学博客，首篇是加州大学圣塔芭芭拉分校粒子理论学者、现为 OpenAI 访问科学家的 Nathaniel Craig 的客座文章。他写道，自己原本有一套在时空格点上给标准模型非微扰定义的思路，但没能证明它覆盖所有需要的情形；在 10 月的预印本里，GPT-6 Astra「帮助把这个思路变成了构造，并主导了详细证明」。他称这只是一个候选定义，连续时空极限仍未解决，并提到 OpenAI 近期的 Yang–Mills 存在性证明补上了关键一块，可证明包含标准模型规范场和费米子的最简单统一理论存在。Greg Brockman 分享时称其为「GPT-6 Astra 用于理论物理」。
3. **Claude Code Projects can now use different models for the coordinator and threads**: TestingCatalog noted that Claude Code Project settings now let you pick separate models for the Coordinator and for Threads, alongside smaller recent upgrades such as custom views that artifacts can be assigned to; in replies it explained that a Project’s goal is set in Project settings > General and the coordinator hands out the work, so a per-session /goal would compete with it. > [zh] **Claude Code Projects 可为协调者和子线程分别选模型**：TestingCatalog 指出，Claude Code 的 Project 设置里现在能给 Coordinator 和 Threads 分别指定模型，近期还有一些小升级，比如可建自定义视图并把产物归到视图里；他在回复里解释，Project 的目标在「Project settings > General」里设定，由协调者分派工作，所以再给单个会话设 /goal 会和它冲突。另外，宝玉分享了自己的分工：主会话用 Sonnet 5.5 负责甄别和路由，子任务用 Opus 5.5；主会话缓存过期后只重发最近几条消息，再配合会话检索工具补齐上下文。
4. **“No AI Slop” manifesto gathers 500+ signatures**: written by speakers and attendees of AI Engineer Code Summit 2026 and modeled on the 2001 Agile Manifesto, it sets five pairs: outcomes over output, understanding over speed, your own thinking over the model’s first draft, better work over easier work, and improving the system over patching the output. It defines slop as putting in less thought than you ask the recipient to spend understanding it, and says using AI is not slop by itself. Per @shao__meng’s write-up, Dex Horthy highlighted that judgment cannot be outsourced and that people should still review plans, designs or results; signatures are collected as comments on his GitHub Gist (504 listed at the time), and the HN thread had about 222 points and 133 comments. https://www.slopmanifesto.com/ | https://x.com/shao__meng/status/2122156731300212773
> [zh] **「No AI Slop」宣言签名超 500**：由 AI Engineer Code Summit 2026 的演讲者和参会者共同写成，参照 2001 年敏捷宣言提出五组对照：结果重于产量、理解重于速度、自己的思考重于模型初稿、更好的工作重于更省事的工作、改进系统重于修补输出。宣言把 slop 定义为「你投入的心思，少于你要求接收者花在理解上的精力」，并说用了 AI 本身不等于 slop。据 @shao__meng 整理，Dex Horthy 强调判断不能外包，人仍应审核计划、设计或结果；签名方式是在他的 GitHub Gist 下留言（当时已列 504 个），Hacker News 讨论约 222 分、133 条评论。

1. **Voxyz: six copy-paste prompts so you stop using Fable 5.2 “like an intern”**: instead of “find the bugs” or “why is CI so slow,” the thread gives six named prompts: the State Machine Hunter (find all implicit state machines and improve UX, DX and agent experience without breaking anything), the Open-Source Scout (search GitHub and compare existing approaches before writing an unfamiliar feature), the Bug Triager (score each bug 1–10 on frequency and severity and only file an issue if the product is below 5), the Closer (finish the whole job, ask before deleting, end with a plain recap), the CI Auditor (pull the last 150 CI runs with gh and split each job into queue, setup and run time), and the Rebuilder (“If you were starting over today with the same goal, what would you still need to keep?”). It had about 6,900 bookmarks at fetch. https://x.com/Voxyz_ai/status/2122011755240984607
> [zh] **Voxyz：六条可直接复制的提示词，别再把 Fable 5.2 当实习生用**：与其说「找 bug」或「CI 为什么慢」，这条串给了六个有名字的提示词：状态机猎手（找出应用里所有隐式状态机，在不破坏功能的前提下同时改善用户体验、开发体验和 Agent 体验）、开源侦察兵（写不熟悉的功能前先去 GitHub 搜开源项目、比较做法）、Bug 分诊员（按发生频率和严重程度各打 1–10 分，乘积低于 5 只记 issue 不改代码）、收尾者（做完整件事再停，删东西前先问，最后给没看过过程的人一段平实总结）、CI 审计员（用 gh 拉最近 150 次 CI 运行，把每个 job 拆成排队、准备和实际执行三段时间）、重建者（「如果今天从头开始、目标不变，你还必须保留什么？」）。抓取时约 6,900 次收藏。

4. **李博杰：为什么 personal agent 都要给每个用户配一台虚拟机？**：他质疑现在的 personal agent 普遍给每个用户分一个云端虚拟机沙盒，每月成本几十美元。他做第一个 agent 时的基本假设是一个 Go 服务支撑多个并发用户，浏览器用无头浏览器，用户文件放 GCS 或 Google Drive 这类虚拟文件系统，也没想到有人敢把 API key 放进沙盒。他还提到自己用 Claude Code 时，一个 session 跑几天后会占 5GB 内存、CPU 常到 100%，并调侃不少产品只是把 OpenClaw、Codex 或 DeepSeek Harness 换壳装进虚拟机。https://x.com/bojie_li/status/2121958983930163268
> [en] **Bojie Li: why does every personal agent give each user a VM?**: he questions why today's personal agents commonly give each user a cloud VM sandbox costing tens of dollars a month. When he built his first agent, the baseline assumption was one Go service serving many concurrent users, a headless browser for the web, and a virtual file system such as GCS or Google Drive for uploads; he never imagined putting API keys inside a sandbox. He also notes that a Claude Code session running for days grew to 5 GB of memory and often pegged the CPU at 100%, and quips that many products just rewrap OpenClaw, Codex or DeepSeek Harness inside a VM.
