## 有趣用法和干货
1. **Matt Pocock’s “comments considered harmful” cleanup prompt**: have the agent categorise every code comment as Tautology (repeats the code), Excuse (lets the agent get away with a hacky implementation), Stale, or Decision Record; delete tautologies and stale ones, delete excuses and file an issue to fix the hack, move decision records into ADRs; then add a lint rule banning comments with a ratchet approach, create a /delete-comment skill to repeat the process, and estimate how many lines you’ll shed (about 3,100 likes, 5,400 bookmarks). poteto pushes the same idea with /no-comments in pstack—“or better yet, ask your agent to turn it into a lint rule”—and pstack v0.15.46 also prunes its skills and adds Gemini 4 Neon as a panel reviewer. https://x.com/mattpocockuk/status/2123798388227403983 [poteto /no-comments](https://x.com/poteto/status/2123898792487576021) [pstack v0.15.46](https://x.com/poteto/status/2123824683862855898)
> [zh] **Matt Pocock 的「注释有害」清理提示词**：让 Agent 把代码里每条注释分成四类：同义反复（重复代码已表达的内容）、借口（让 Agent 蒙混过关写出凑合实现）、过时、决策记录；同义反复和过时的直接删，借口类删掉并开 issue 修复凑合实现，决策记录挪进 ADR；然后加一条禁止注释的 lint 规则并采用渐进收紧（ratchet）策略，建一个 /delete-comment skill 便于以后重复，再估算能删掉多少行（约 3100 赞、5400 收藏）。poteto 也在推 pstack 的 /no-comments——「或者更好：让你的 Agent 把它变成 lint 规则」；pstack v0.15.46 同时精简了 skills，并加入 Gemini 4 Neon 作为评审成员。
2. **Gemini API ships Dynamic Tool Retrieval (Tool Search Tool) in preview**: Philipp Schmid’s write-up: add {"type": "tool_search"} and set defer_loading: true on functions or remote MCP servers, and Gemini sees only a one-line summary per tool (about 26 tokens), searching and loading full schemas inside the same request so your prompt prefix stays cacheable—keep your 3–5 most-used tools loaded and defer the long tail. Or declare a client-side tool_search ("execution": "client") and run your own retrieval—vector search, per-user permission filtering, or scoring candidates with the Gemini Decisions API (gemini-decision-1) at zero output tokens. No extra fee; tool declarations aren’t carried across turns, so resend the full tools array each request. https://x.com/_philschmid/status/2123806307442401577 [Announcement](https://x.com/_philschmid/status/2123806623114440911)
> [zh] **Gemini API 预览上线动态工具检索（Tool Search Tool）**：Philipp Schmid 的说明：在 tools 里加 {"type": "tool_search"}，并给函数或远程 MCP 服务器设 defer_loading: true，Gemini 每个工具只看到一行摘要（约 26 token），需要时在同一次请求里搜索并加载完整 schema，提示词前缀因此保持可缓存——把最常用的 3–5 个工具常驻，长尾的延迟加载。也可以声明客户端 tool_search（"execution": "client"）自己做检索：向量搜索、按用户权限过滤，或用 Gemini Decisions API（gemini-decision-1）零输出 token 给候选工具打分。不额外收费；工具声明不会跨轮保留，每次请求都要重发完整 tools 数组。
3. **“LM Harnesses are Compositional Generalizers”: why harnesses won’t get absorbed into models**: Alex Zhang (with @SOURADIPCHAKR18 and Omar Khattab) argues that with stronger models, harness abstractions let LM systems generalize over task length, strategy and recursive depth by composing existing capabilities; keeping every individual LLM call “locally in-distribution” makes training on long tasks more data-efficient and even enables “surrogate harness training” on synthetic tasks with fake tool calls and sub-agents—paper, logs, code and data are all released (about 1,100 bookmarks). Sebastian Raschka adds that models are fine-tuned to specific harnesses and tools, so “the model can't really absorb it… a bit like the CPU/GPU absorbing the operating system.” https://x.com/a1zhang/status/2123774098241147225 [Sebastian Raschka](https://x.com/rasbt/status/2123853084216455549) [elvis](https://x.com/omarsar0/status/2123863490800828830)
> [zh] **《LM Harnesses are Compositional Generalizers》：为什么 harness 不会被模型吸收**：Alex Zhang（与 @SOURADIPCHAKR18、Omar Khattab）认为，模型变强之后，harness 的抽象可以通过组合模型已有能力，让 LM 系统在任务长度、策略和递归深度上泛化；让每一次单独的 LLM 调用都保持「局部在分布内」，长任务训练会更省数据，甚至可以用带假工具调用和子 Agent 的合成任务做「代理 harness 训练」——论文、日志、代码和数据全部公开（约 1100 收藏）。Sebastian Raschka 补充：模型本来就是针对特定 harness 和工具微调的，「模型其实吸收不了它……有点像让 CPU/GPU 吸收操作系统」。
4. **Paper: a 27B open model rewrites its own weights—no gradients, no training**: “Language Models Can Rewrite Their Own Weights” gives an open 27B model its weights, its graded answers and the ability to run itself; it diagnoses its failures and edits the weights behind them, gaining 6.6 points on unseen problems, improving across eight consecutive sessions, and restoring a damaged copy of itself to over 80% of the original accuracy on unseen image tasks; in one model family only the largest model manages it, while smaller ones make no edit or break themselves. The gain lives in the weights at no per-answer cost and needs only forward passes (HN 350+ points). https://arxiv.org/abs/2611.21885 [HN](https://news.ycombinator.com/item?id=50577265) [Rohan Paul](https://x.com/rohanpaul_ai/status/2123828039276773655)
> [zh] **论文：27B 开源模型自己改写自己的权重，不用梯度、不用训练**：《Language Models Can Rewrite Their Own Weights》把权重、已评分的答案和运行自身的能力交给一个开源 27B 模型，它会诊断自己的失败并改写相应权重：在没见过的题上准确率提高 6.6 个百分点，连续八轮会话持续变好，还能把一个受损的自身副本在没见过的图像任务上恢复到原准确率的 80% 以上；同一模型家族里只有最大的模型做得到，小模型要么不改、要么把自己改坏。收益写进权重、每次回答没有额外成本，只需要前向计算（HN 350+ 分）。
