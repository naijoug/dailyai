2. **Trix**: a terminal workspace built around coding agents (Show HN). Agents report their own state—working, needs you, done, idle, unseen—instead of trix scraping the screen; a red bar, desktop notification and bell fire when one waits on you, `alt+a` jumps to the one that has waited longest, and `alt+g` shows all agents side by side. Each agent can run in its own git worktree, agents keep running in a background server after you close the terminal, and a CLI (`trix spawn`, `send`, `wait`, `read`) lets scripts or other agents drive them; it supports Claude, Codex, Grok, OpenCode, Cursor, Copilot, Muse, Gemini, Antigravity, Amp and any CLI. https://trixapp.ai/ [HN](https://news.ycombinator.com/item?id=50605218)
> [zh] **Trix**：围绕编程 Agent 设计的终端工作区（Show HN）。由 Agent 主动上报状态——工作中、需要你、完成、空闲、未查看——而不是靠抓屏猜；有 Agent 等你时会弹红条、桌面通知和提示音，`alt+a` 跳到等得最久的那个，`alt+g` 并排查看所有 Agent。每个 Agent 可在独立 git worktree 里工作，关掉终端后仍在后台服务器里继续跑，还有 CLI（`trix spawn`、`send`、`wait`、`read`）供脚本或其他 Agent 调度；支持 Claude、Codex、Grok、OpenCode、Cursor、Copilot、Muse、Gemini、Antigravity、Amp 及任意 CLI。
3. **Taskless**: “Rules for Agents” (Show HN)—you tell it a convention, for example from a PR comment like “no any in exported types,” and it compiles that into a deterministic check with its own pass/fail fixtures that runs on every commit, PR and IDE session with no model in the loop. Its pitch is that AGENTS.md, skills and `.cursor/rules` only inject markdown and hope the model listens; rules go into your existing linter’s dialect where possible, cover 25+ languages plus prose, run locally via `npx @taskless/cli` without an account, with a Cloud tier for cross-file checks. https://www.taskless.io/ [HN](https://news.ycombinator.com/item?id=50603421)
> [zh] **Taskless**：「给 Agent 的规则」（Show HN）——你说一条约定，比如 PR 评论里的「导出类型不许用 any」，它就编译成一条带通过/失败用例的确定性检查，在每次提交、PR 和 IDE 里运行，运行时不需要模型参与。它的论点是 AGENTS.md、skills 和 `.cursor/rules` 只是往提示词里塞 markdown、指望模型听话；规则尽量写成你现有 linter 的方言，支持 25 种以上语言和文字内容，`npx @taskless/cli` 本地即可运行、无需注册，跨文件检查等复杂情况用 Cloud 版。

## 科技新闻
1. **The Lean formalization of Masullo’s 940-page GRH manuscript has logged about 245 false statements**: built in the open “by people and their coding agents,” the project says that as of November 22 about 6,800 theorems and 1,290 definitions are stated in Lean and about 6,100 theorems proved, from some 1,580 merged pull requests by about thirty people. Its ERRATA file has about 660 entries—roughly 245 statements false as printed, 345 imprecise or wrongly justified—and 22 steps in Chapters 5–7 that later results depend on have no repair yet; the project assumes neither that the main claim is right nor wrong. The progress map, published as a Claude artifact, hit 168 points on HN, where commenters warned a progress bar says little when one hole can sink the proof. https://github.com/mccorvie/riemann-masullo https://claude.ai/artifact/CtQyX8qfYAF822bgHJHHE3 [HN](https://news.ycombinator.com/item?id=50605045)
> [zh] **Masullo 940 页广义黎曼猜想手稿的 Lean 形式化，已记录约 245 处错误陈述**：这个「由人和他们的编程 Agent」公开推进的项目称，截至 11 月 22 日，约 6800 条定理和 1290 个定义已写成 Lean，其中约 6100 条定理已证明，来自约 30 人合并的约 1580 个 PR。勘误文件约有 660 条——约 245 条陈述按原文是错的，345 条不精确或论证有误——第 5–7 章有 22 个被后续结果依赖的步骤尚无修复方案；项目既不预设主结论正确，也不预设它错误。以 Claude artifact 发布的进度图在 HN 拿到 168 分，评论提醒：一个漏洞就能推翻整个证明，进度条说明不了太多。
2. **The New Stack: GPT-6.2 Astra and Claude Fable 5.2 nearly tie on hard custom tasks, but Fable costs 5x more**: after GPT-6.2 Astra’s 20% price cut brought its list price to $8/$40 per million tokens, identical to Fable 5.2, Jessica Wachtel ran three tests made harder until GPT-5 struggled. Both scored 173/173 on an agentic month-end close, Fable 5.2 scored 110/110 vs. Astra’s 108 on a bug-ridden billing library, and both got 76/76 on messy lab data; but Fable used about 1.75M input and 104k output tokens vs. Astra’s 488k and 13k, costing $7.60 vs. $1.45 and taking 917 vs. 232 seconds.
