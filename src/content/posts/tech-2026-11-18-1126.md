## 新产品
1. **MAI Code 2**: Microsoft AI’s new coding models for everyday enterprise work. MAI Code 2 targets production changes, deep debugging, multi-file implementation, repo-wide reasoning and UI; averaged over DeepSWE 1.1, Terminal Bench 2.1, SWE-Atlas and FrontierCode v1.1, Microsoft says it gets 98% of GPT-6.1 Sol’s performance at 40% of the cost and 96% of Claude Opus 5.5’s at 5%, and blind reviewers preferred its frontend apps over GPT-6 Sol 64% of the time. MAI Code 2 Flash is for high-volume edits and explanations, roughly matching GPT-6 Luna and Claude Haiku 5.5 at 65% and 20% of their cost (costs shown at a 50% promo price). Microsoft says they are explicitly not tuned yet for fundamental science or very long-horizon agent work. Both are in GitHub Copilot, Flash is in limited preview on Foundry, and OpenRouter, Vercel, Hermes, OpenCode and Kilo are next (HN discussion: https://news.ycombinator.com/item?id=50535885). https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/
> [zh] **MAI Code 2**：微软 AI 面向日常企业开发的新编程模型。MAI Code 2 主攻上线级改动、深度调试、多文件实现、全仓推理和 UI；按 DeepSWE 1.1、Terminal Bench 2.1、SWE-Atlas、FrontierCode v1.1 四项平均，微软称它以 40% 的成本达到 GPT-6.1 Sol 98% 的表现，以 5% 的成本达到 Claude Opus 5.5 的 96%；盲评中评审有 64% 的时候更喜欢它做的前端应用而非 GPT-6 Sol。MAI Code 2 Flash 面向大批量的修改和代码解释，表现与 GPT-6 Luna、Claude Haiku 5.5 相当，成本分别为其 65% 和 20%（按 5 折推广价计）。微软明确表示它们还没针对基础科研和超长程 Agent 任务调优。两款已上 GitHub Copilot，Flash 在 Foundry 限量预览，之后将上 OpenRouter、Vercel、Hermes、OpenCode 和 Kilo。
2. **StarSling**: fast GitHub Actions runners with agents that open PRs to speed up your CI (Launch HN, YC P25). Each job gets an ephemeral sandbox on Zen 5 machines with NVMe and unlimited concurrency so a burst of agent PRs runs at once; a CI harness loops agents over workflows, run logs and telemetry to propose fixes. The founders say Mastra, which merges 1,800+ PRs a month, saw its slowest workflow drop from 29m56s to 5m06s, and an agent found an 11-month-old bottleneck in better-auth that made a test job 5.4x faster. It bills per second, adds persistent “StarSling Disks” (4.9x faster dependency setup than actions/cache), and open-sources /ci-speedup, /ci-score and /ci-secure skills for your own coding agent (HN: https://news.ycombinator.com/item?id=50536468). https://starsling.dev
> [zh] **StarSling**：自带 Agent 的高速 GitHub Actions 运行器，Agent 会主动提 PR 给你的 CI 提速（Launch HN，YC P25）。每个任务跑在 Zen 5 + NVMe 的临时沙箱里，并发不设上限，大批 Agent PR 能同时跑；CI harness 让 Agent 循环分析工作流、运行日志和机器遥测并提出优化。创始人称，每月合并 1,800 多个 PR 的 Mastra 最慢的工作流从 29 分 56 秒降到 5 分 06 秒，Agent 还在 better-auth 里揪出一个存在 11 个月的性能瓶颈，让一个测试任务快了 5.4 倍。按秒计费，新增持久化的 StarSling Disks（依赖就绪比 actions/cache 快 4.9 倍），并开源了 /ci-speedup、/ci-score、/ci-secure 三个可给自家编程 Agent 用的 skill。
3. **TrnRT**: RunAnywhere (YC W26) open-sourced an LLM inference engine for AWS Trainium, built in three weeks because vLLM Neuron didn’t register GLM models and AWS’s NxDI is no longer actively developed (Show HN). It serves GLM-5.3-Flash (FP8, 1M context) behind an OpenAI-compatible API from one trn2.48xlarge, running decode as one NKI megakernel per layer half, with sparse plus linear attention and a radix-tree prefix cache over FP8 KV pages that spills to host memory. On SemiAnalysis’s AgentX replay of real coding-agent sessions, one box handled 28.9 requests a minute with 32 agents and about 3.57M tokens per minute; the pitch is that memory per TB on trn2 costs less than half of 8x H200 on AWS. https://github.com/RunanywhereAI/trnrt
> [zh] **TrnRT**：RunAnywhere（YC W26）开源的 AWS Trainium 大模型推理引擎，三周做成，起因是 vLLM Neuron 不支持 GLM 模型、AWS 自家的 NxDI 已不再积极开发（Show HN）。它在一台 trn2.48xlarge 上以 OpenAI 兼容 API 提供 GLM-5.3-Flash（FP8、100 万上下文），解码时每半层一个 NKI 融合大内核，支持稀疏注意力和线性注意力，并用基数树管理 FP8 KV 页的前缀缓存、溢出到主机内存。在回放真实编程 Agent 会话的 SemiAnalysis AgentX 基准上，一台机器 32 个 Agent 并发时每分钟处理 28.9 个请求、约 357 万 token；卖点是 trn2 每 TB 显存的成本不到 AWS 上 8 卡 H200 的一半。
4. **Agav**: an Apache-2.0 terminal coding agent built to waste fewer tokens (Show HN): it reuses cached context, limits repeated work, interrupts unproductive repair loops, bounds retries and budgets, and isolates subagent exploration instead of resending repo context. In its own Terminal-Bench 2.1 cost study with GPT-5.6 Luna, it spent 49.1% less than Codex (15.2¢ median per trial over 89 tasks), but the authors stress it’s a cost result: Agav passed 60.4% of trials vs. Codex’s 76.6%. It works with Anthropic, OpenAI, OpenRouter, NVIDIA NIM, Gemini, Vertex AI or Ollama, with per-action permissions and sandboxed commands on macOS and Linux. https://agav.dev
> [zh] **Agav**：Apache 2.0 开源的终端编程 Agent，主打少浪费 token（Show HN）：复用缓存上下文、减少重复劳动、打断无效的修复循环、限制重试次数和预算，子 Agent 探索相互隔离，不反复发送整仓上下文。在其用 GPT-5.6 Luna 做的 Terminal-Bench 2.1 成本研究中，总花费比 Codex 少 49.1%（89 道题每次试跑中位成本 15.2 美分），但作者强调这只是成本结论：Agav 通过率 60.4%，Codex 为 76.6%。支持 Anthropic、OpenAI、OpenRouter、NVIDIA NIM、Gemini、Vertex AI 和 Ollama，工具按操作授权，macOS 和 Linux 上命令可在沙箱中运行。
5. **Cerebras Disaggregated Inference**: Cerebras now runs prefill on GPUs and decode on its wafer-scale systems in production, claiming five times more tokens per megawatt at the same ultrafast speeds; in its Inference Cloud deployment AMD Instinct GPUs process prompts and CS-3 systems generate responses. It plans to roll this across hundreds of megawatts by the end of 2027 and offers a reference architecture for partners to pair their own prefill accelerators with Cerebras systems, citing agentic apps like Muse, Copilot and Codex as the demand driver (HN: https://news.ycombinator.com/item?id=50540472). https://www.cerebras.ai/blog/cerebras-launches-disaggregated-inference
> [zh] **Cerebras 分离式推理**：Cerebras 已在生产环境中让 GPU 负责预填充、自家晶圆级系统负责解码，称在保持超快速度的同时，每兆瓦产出的 token 提高到 5 倍；其推理云的部署中由 AMD Instinct GPU 处理提示词、CS-3 生成回复。计划到 2027 年底在数百兆瓦规模上铺开，并为合作伙伴提供参考架构，可把自选的预填充加速器与 Cerebras 系统搭配使用；它把 Muse、Copilot、Codex 等 Agent 应用列为需求来源。

## 科技新闻
1. **Java4Shell: a critical RCE in OpenJDK’s Base64 decoder, found with AI**: Calif disclosed CVE-2026-114938 (CVSS 4.0 9.2): on x86-64 CPUs with AVX-512 VBMI, malformed Base64 such as 64 “A”s plus “=” makes the hand-written intrinsic compute a negative length and overwrite heap memory, which Calif turned into Heartbleed-style leaks and remote code execution. It affects OpenJDK 17.0.6 and newer (ARM64 is not affected); Calif demonstrated pre-auth RCE in default configs of apps like Keycloak, Jira, Confluence and Jenkins, and in Struts and Spring Boot samples. Calif says a researcher found it in an hour and had a first exploit two hours later for under $200 in tokens; Greg Brockman credited GPT-6 Cyber under OpenAI’s Patch the Planet effort. Oracle and OpenJDK shipped fixes on Nov 17; until you patch, -XX:-UseBASE64Intrinsics disables the fast path (HN, 600 points: https://news.ycombinator.com/item?id=50538240). https://calif.io/java4shell/
> [zh] **Java4Shell：AI 协助发现的 OpenJDK Base64 解码器高危 RCE**：Calif 披露 CVE-2026-114938（CVSS 4.0 评分 9.2）：在支持 AVX-512 VBMI 的 x86-64 CPU 上，像「64 个 A 加一个 =」这样的畸形 Base64 输入会让手写的内联汇编算出负长度并覆写堆内存，Calif 借此实现了心脏出血式的内存泄露和远程代码执行。影响 OpenJDK 17.0.6 及以上版本（ARM64 不受影响）；Calif 在 Keycloak、Jira、Confluence、Jenkins 等应用的默认配置下演示了免认证 RCE，Struts 和 Spring Boot 示例应用也中招。Calif 称研究员一小时就发现了漏洞，又用两小时写出首个利用，token 花费不到 200 美元；Greg Brockman 称这是 GPT-6 Cyber 在 OpenAI「Patch the Planet」计划下的成果。Oracle 和 OpenJDK 已于 11 月 17 日发布修复；打补丁前可用 -XX:-UseBASE64Intrinsics 关闭这条加速路径。

Each model had a different best-value harness: Codex CLI with GLM-5.3, Pi with GLM-5.3 Flash, ZCode with DeepSeek V4.1 Flash, Oh My Pi with Muse and Alma with Kimi-K3; by cost per task the median harness moved 11 of 22 places between models, and Codex CLI went from 1st with GLM-5.3 to 16th with Kimi-K3. Across all models only OpenCode v2 (cheapest, $0.561 a task), Pi, Codex CLI and ZCode (highest pass rate, 61.9%) sit on the cost/pass-rate frontier (HN, 341 points: https://news.ycombinator.com/item?id=50532191). https://runta.com/blog/introducing-frontierharness-eval-v1-1/
> [zh] **FrontierHarness v1.1 最终结果：换模型时也该换 harness**：Runta 和 Baseten 花了 830 亿 token 跑 27,280 次（22 套 harness 配置 × 5 个开放权重模型 × 62 道终端任务 × 每题 4 次）。每个模型的最佳性价比 harness 都不同：GLM-5.3 配 Codex CLI、GLM-5.3 Flash 配 Pi、DeepSeek V4.1 Flash 配 ZCode、Muse 配 Oh My Pi、Kimi-K3 配 Alma；按单任务成本排名，中位 harness 换个模型就会移动 22 位中的 11 位，Codex CLI 从 GLM-5.3 上的第 1 跌到 Kimi-K3 上的第 16。综合所有模型，只有 OpenCode v2（最便宜，每题 0.561 美元）、Pi、Codex CLI 和 ZCode（通过率最高，61.9%）处在成本与通过率的前沿线上。
