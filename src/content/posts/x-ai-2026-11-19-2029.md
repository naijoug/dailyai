## 有趣用法和干货
1. **Bojie Li：长任务让 subagent 干活，主会话只用来聊天**：用 Claude Code / Codex 跑长程任务时，默认在主会话里干活，问个问题往往要等它把手头的事收尾才回答，满屏执行细节也让几小时前的对话很难翻。改成主会话陪你讨论、subagent 在后台执行，界面清爽很多；他说这相当于把 Claude/Codex 改造成了 OpenClaw，DeepSeek superagent 也是这种架构。https://x.com/bojie_li/status/2123335123232031209
> [en] **Bojie Li: for long tasks, let a subagent do the work and keep the main session for talking**: by default Claude Code / Codex work in the main session, so a question often waits minutes until the current step wraps up, and execution noise makes hours-old discussion hard to scroll back to. Having the main session chat with you while subagents execute in the background keeps things clean; he says this effectively turns Claude/Codex into OpenClaw, and DeepSeek’s superagent uses the same architecture.
2. **rust-anything：先录下原程序行为，再让 Agent 一块块改写成 Rust**：GitHub Daily 推荐的开源工具，支持 Node.js、Python、C、Go、Ruby、Java 项目：record 先跑原程序记录各种边界输入的输出，Agent 写完一块 Rust 就用 diff 逐条回放比对，全部对上才往下走，最后可整体变成纯 Rust；也可以只迁最慢的热点。README 给的数据：Prettier 格式化 2360 个 JS/TS 文件从 128.6 秒降到 6.9 秒，Fuse.js 5 万条搜索每次从 91.2 毫秒降到 2.8 毫秒；作者也写明只能抓到录制覆盖到的行为。https://x.com/GitHub_Daily/status/2123317868188287190 [GitHub](https://github.com/erkamyaman/rust-anything)
> [en] **rust-anything: record the original program’s behavior, then let an agent port it to Rust piece by piece**: an open-source tool highlighted by GitHub Daily for Node.js, Python, C, Go, Ruby and Java projects: `record` runs the original on edge-case inputs, and after the agent writes each Rust piece, `diff` replays every recorded case and only moves on when all match, eventually lifting to a pure Rust app; you can also port just the slowest hot path. README numbers: Prettier on 2,360 JS/TS files drops from 128.6s to 6.9s, and Fuse.js search over 50,000 strings from 91.2ms to 2.8ms per query; the author notes it can only catch what the recording covers.
3. **CMU 17-214 第 21 讲：Agent 一下午改 2000 行，检查就得做成流水线门禁**：shao__meng 拆解了 CMU「Agentic Software Development」课程的「Verification in the Pipeline」讲义：有人带着 Agent 一下午开出 2000 行的 PR，认真审完仍要几小时，所以要把测试、类型检查、代码检查做成每次改动都跑的合并门禁；动态检查和静态检查抓的问题不同，讲义用一段「伪造通知总成功、真实邮件失败却让进程退出」的预订代码说明静态检查的价值。https://x.com/shao__meng/status/2123278617497186713 [课程](https://cmu-17-214.github.io/f2026/)
> [en] **CMU 17-214 Lecture 21: when an agent changes 2,000 lines in an afternoon, checks must become pipeline gates**: shao__meng breaks down the “Verification in the Pipeline” slides from CMU’s Agentic Software Development course: someone with an agent opens a 2,000-line PR in an afternoon and a careful review still takes hours, so tests, type checks and linters should be merge gates on every change; dynamic and static checks catch different problems, illustrated by booking code whose faked notifier always succeeds in tests while a real email failure would crash the process.
