## 有趣用法和干货
1. **Thorsten Ball: “How to Not Use Agents in November ’26”**: his note (2k bookmarks) says “How you used agents 3 months ago might now be theater.” The list: don’t review code before the agent has run and tested it; ask for proof instead of only reading diffs (test confirmation, end-to-end videos, screenshot test matrices, traces, benchmarks); stop treating model and effort picking as a fidget toy; don’t pile on skills and tools you don’t understand; give the agent “maintenance shafts” to exercise the codebase end to end; run the numbers on cheap models, which may need more turns; let it handle the whole SDLC (verify, ship, watch error rates, roll out in 10% steps); don’t hide production logs; put “how things are done” in the codebase, not your head; let frontier models split work themselves instead of prescribing subagents; run agents on remote machines, not just your laptop; and trust compaction instead of watching context percentages. https://x.com/thorstenball/status/2126006279176921404
> [zh] **Thorsten Ball：《2026 年 11 月，别再这样用 Agent》**：他的这篇笔记（2k 收藏）开头就说「你三个月前用 agent 的方式，现在可能只是在演戏」。清单包括：别在 agent 自己跑过、测过之前就去审代码；与其逐行看 diff，不如让它拿出证据（测试结果、端到端录屏、带截图的测试矩阵、trace、基准）；别把挑模型、调 effort 当解压玩具；别塞一堆自己都不懂的 skill 和工具；给 agent 留好能端到端跑通代码库的「检修通道」；用便宜模型前先算账，它可能要多跑很多轮；让它接管整个开发流程（验证、上线、盯错误率、按 10% 逐步放量）；别对它隐藏生产日志；把「这里的规矩」写进代码库而不是留在脑子里；让前沿模型自己拆任务，别手动规定子 agent 分工；把 agent 放到远程机器上跑，而不只是笔记本；相信自动压缩，别再盯着上下文占用百分比。
2. **Philipp Schmid: why he is bullish on MCP for 2027**: in an X Article (741 bookmarks) he argues MCP is past its backlash, citing agents creating about half of all issues and pages at Linear and Notion, 5M+ MCP tool calls per workday at Atlassian, and Apple shipping local MCP servers for iWork. His four reasons: Code Mode plus `outputSchema` lets harnesses generate typed stubs so one script chains many calls; the Skills extension serves SKILL.md over `skill://` URIs with SHA-256 digests so teams get updates automatically; the MCP Events extension (webhook, push stream or poll) lets servers wake always-on agents; and MCP Apps render interactive HTML views in clients. Still unsolved: servers can’t see user intent, discovery across registries, and a wider prompt-injection surface. His advice: expose tools for agents, not agents as tools. https://x.com/_philschmid/status/2125945282072297794
> [zh] **Philipp Schmid：为什么他看好 2027 年的 MCP**：他在一篇 X 长文（741 收藏）里认为 MCP 已走出低谷，依据包括 Linear 和 Notion 约一半的 issue 和页面由 agent 创建、Atlassian 每个工作日 500 万次以上 MCP 工具调用、苹果为 iWork 推出本地 MCP 服务器。他的四个理由：Code Mode 加 `outputSchema` 让 harness 预先生成带类型的桩函数，一段脚本串起多次调用；Skills 扩展用带 SHA-256 摘要的 `skill://` URI 下发 SKILL.md，团队自动拿到更新；MCP Events 扩展（webhook、推送流或轮询）让服务端能唤醒常驻 agent；MCP Apps 在客户端里渲染可交互的 HTML 视图。尚未解决的：服务端看不到用户意图、跨注册表的发现，以及更大的提示注入面。他的建议：给 agent 提供工具，而不是把 agent 包成工具。
3. **Two papers on making agents cheaper to feed context: NVIDIA lets models manage their own context, Ramp translates KV state between models**: in “Letting Models Manage Their Own Context: Where We Stand”, NVIDIA gives models a context API in its open-source NOOA harness so the model, not the harness, decides when and what to compact; at a 32K budget GPT-6.1 went from 21% to 56% on OfficeQA Pro v2, Kimi used up to 41% fewer input tokens, and reusing the KV cache of the unchanged suffix after an edit cut prefill compute by up to 15% with no measurable accuracy change (omarsar0’s summary drew 461 bookmarks). Ramp Labs’ “speculative encoding” is a 2.35B MoE that translates one model’s hidden states into an approximate cache for another, keeping 96.9% of base accuracy across 7 models and cutting prefill latency up to 7.5× on long documents, aimed at multi-agent swarms and model routing. https://arxiv.org/abs/2611.34147 https://x.com/omarsar0/status/2125961781743075565 https://x.com/RampLabs/status/2125627502802653330
> [zh] **两篇让 agent 喂上下文更便宜的研究：英伟达让模型自己管上下文，Ramp 在模型间翻译 KV 状态**：英伟达在《让模型自己管理上下文：现状》里，给开源 agent harness NOOA 加了上下文 API，由模型而非 harness 决定何时压缩、压缩什么；在 32K 预算下 GPT-6.1 在 OfficeQA Pro v2 上从 21% 升到 56%，Kimi 最多少用 41% 输入 token；编辑后复用未改动后缀的 KV 缓存，可把 prefill 计算量最多降 15% 且准确率无可测变化（omarsar0 的解读获 461 收藏）。Ramp Labs 的「speculative encoding」是一个 2.35B 的 MoE，把一个模型的隐藏状态翻译成另一个模型可用的近似缓存，在 7 个模型上保持 96.9% 的原始准确率，长文档 prefill 延迟最多降 7.5 倍，面向多 agent 集群和模型路由场景。
