## 有趣用法和干货
1. **Vox: paste a “Linear-level simplicity” brief before your next app (11k+ bookmarks)**: “I want this to be as perfect as Linear's website or Apple Notes: simple purpose, simple architecture, simple design, simple implementation. Cut taglines, helper text and secondary labels. If a screen needs them to make sense, fix the layout…” and every decision should improve UX, DX and agent experience (AX) at once. https://x.com/Voxyz_ai/status/2117281830449942825
> [zh] **Vox：做下一个网站 / App 前，先贴一段「Linear 级极简」提示词（1.1 万+ 收藏）**：「我希望它像 Linear 官网或 Apple Notes 一样完美：目的简单、架构简单、设计简单、实现简单。删掉口号、辅助文字和次要标签；如果某个页面离开它们就看不懂，就改布局……」并要求每个决策同时提升 UX、DX 与 Agent 体验（AX）。
2. **Philipp Schmid: will agents end up with just one tool? A write-up on Code Mode**: tools went from a handful, to dynamic tool search, to collapsing everything into code mode; his post explains how it works, why a typed JS/Python sandbox can beat raw bash, why he expects MCP to come back strong in 2027, with a minimal Gemini 4 Argon example (he suggests testing with pi). https://x.com/_philschmid/status/2117278154918092817 | https://www.philschmid.de/code-mode
> [zh] **Philipp Schmid：Agent 最后会只剩一个工具吗？Code Mode 长文**：从少量工具到动态工具搜索，再到把一切收进代码模式；文章讲清原理、为什么带类型的 JS/Python 沙箱能胜过裸 bash、为何他认为 MCP 会在 2027 年强势回归，并附 Gemini 4 Argon 最小示例（推荐用 pi 试）。
3. **Arpit Bhayani: structure the codebase before asking agents to write tests**: with clear file/directory conventions the model knows where logic lives, mocks the right boundaries and covers more branches first time; on spaghetti code (logic in handlers, global state, five-job functions) it writes brittle or hollow tests. “Messy structure, messy tests.” https://x.com/arpit_bhayani/status/2117246849656697252
> [zh] **Arpit Bhayani：让 Agent 写测试前，先把代码结构理清**：文件和目录约定清晰时，模型知道逻辑在哪、该 mock 哪些边界，一次覆盖更多分支；面对意大利面代码（业务逻辑混在 handler、全局状态、一个函数干五件事）只会写出脆弱或空洞的测试。「结构乱，测试就乱。」
4. **@Gorden_Sun：DecisionRAG 用决策模型做又快又准的检索**：借鉴图书馆查书，把资料库组织成「大类 → 标题 → 段落」层级，Jev 类决策模型单次对同级选项打分逐层筛选；在维基百科 268 万+ 段落上 0.7–1.8 秒完成查找、单次 0.2–2.3 美分，多个问答集上比搜索 + 重排准十几个百分点、比让大模型慢慢找快 30 多倍。https://x.com/Gorden_Sun/status/2117250771851022594 | https://arxiv.org/abs/2610.35868
> [en] **@Gorden_Sun: DecisionRAG uses decision models for fast, accurate retrieval**: like browsing a library, the corpus becomes a category → title → paragraph hierarchy and a Jev-style decision model scores all siblings in one pass, pruning level by level; on 2.68M+ Wikipedia paragraphs it answers in 0.7–1.8 s at 0.2–2.3 cents per query, beating search + rerank by double-digit points and running 30x+ faster than letting an LLM search slowly.
