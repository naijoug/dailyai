1. **OpenAI: how it secures hundreds of persistent OpenClaw agents in-house**: Kevin Lin's post (~230 bookmarks, shared by steipete) links an OpenAI developer blog with concrete controls: run the OpenClaw Gateway in a separate cluster from the agent harness (trusted config vs untrusted agent code); sandbox network (managed allowlist plus explicit denies such as 169.254.169.254), workspace writes, processes and secrets (a credential broker, GH_TOKEN stripped from the shell env); ban danger-full-access and use cached web search, with sample requirements.toml and config.toml; enforce Auto-review on every agent action; give each agent its own identity tied to a ChatGPT service account; and log every config change and turn. OpenAI says 500+ agents now run proactively in the background, and OpenClaw Enterprise (OCE) is aiming for 1.0 by year end. https://x.com/kevins8/status/2120962631788114377 | https://developers.openai.com/blog/securing-persistent-agents-like-openclaw-at-openai
> [zh] **OpenAI 公开内部数百个 OpenClaw 常驻 Agent 的安全做法**：Kevin Lin 的帖子（约 230 收藏，steipete 转发）指向 OpenAI 开发者博客，给出具体措施：OpenClaw Gateway 和 Agent harness 分开部署在不同集群（可信配置与不可信的 Agent 代码隔开）；用沙箱管住网络（组织白名单，并显式拒绝 169.254.169.254 等地址）、工作区写入、进程和密钥（凭据代理，shell 环境里剔除 GH_TOKEN）；禁用 danger-full-access、只用缓存搜索，附 requirements.toml 和 config.toml 示例；所有 Agent 动作强制 Auto-review；每个 Agent 有独立身份并绑定 ChatGPT 服务账号；配置变更和每一轮对话全部记日志。OpenAI 称目前有 500 多个 Agent 在后台主动干活，OpenClaw Enterprise（OCE）计划年底到 1.0。

3. **Voxyz: delete most comments in codebases your agents work in**: agents copy whatever they see, so a single comment explaining a temporary workaround reads as "workarounds are fine here," and the repo fills with copied hacks and stale comments. The post (~140 bookmarks) shares a prompt for Claude Code or Codex: identify useless comments to prune, keep the ones that should exist (like a browser quirk), and return a plan for which workarounds to refactor and which to just delete. https://x.com/Voxyz_ai/status/2120984983330578472
> [zh] **Voxyz：让 Agent 干活的代码库，大部分注释可以删掉**：Agent 会照抄代码库里已有的东西，留一条解释临时绕法的注释，它就理解成「这里可以绕」，久而久之整个仓库都是抄来的 hack 和过期注释。帖子（约 140 收藏）附了一句给 Claude Code 或 Codex 的提示词：找出可以删掉的无用注释，保留真正该留的（比如解释浏览器怪癖的），再给一份高层计划：哪些绕法该重构解决，哪些可以直接删。
