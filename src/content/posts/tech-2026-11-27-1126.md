## 新产品
1. **UI SDK**: the shadcn/ui team’s new library breaks interfaces into 50+ “behaviors” agents can compose instead of finished components—`createPopup`, `createSelection`, `createTypeahead`, `createRovingFocus`, `createReorder`, `createVirtualizer` and more—so from the same pieces an agent can build a Select, a combobox or a component nobody has designed yet, in React, Vue, Svelte, Solid or Web Components. You add the UI SDK skill to your agent rather than using the behaviors by hand, and the site says agents then read the page and work the controls directly without screenshots, “more than twice as fast, at less than half the cost”; source is on GitHub. shadcn’s explainer video drew 1.4k bookmarks, and 宝玉 re-dubbed it in Chinese. https://ui-sdk.dev/ https://x.com/shadcn/status/2126032449582813307 https://x.com/dotey/status/2126070816534151538
> [zh] **UI SDK**：shadcn/ui 团队的新库，不给 agent 成品组件，而是把界面拆成 50 多个可组合的「行为」——`createPopup`、`createSelection`、`createTypeahead`、`createRovingFocus`、`createReorder`、`createVirtualizer` 等——同一套零件既能拼出 Select，也能拼出 combobox 或还没人设计过的组件，可用于 React、Vue、Svelte、Solid 和 Web Components。用法是给 agent 装上 UI SDK skill，而不是自己手写；官网称 agent 还能直接读页面、操作控件而无需截图，「速度快一倍以上，成本不到一半」；源码在 GitHub。shadcn 的讲解视频获 1.4k 收藏，宝玉配了中文配音转发。
2. **WhipDesk**: a free, open-source remote desktop built for babysitting coding agents from a phone browser with no app: smart zoom streams only the part you are looking at so code stays sharp on cellular, “Auto-Whips” alert you when Claude Code, Codex, Gemini CLI, Aider, Copilot CLI, opencode, Cursor Agent or Amp is waiting, finished or crashed, and you can schedule prompts such as a “continue” at 2 AM when your session limit resets, plus one-tap saved prompts and replayable click-and-type macros. It is end-to-end encrypted and installs with `npm install -g whipdesk`; the maker says LAN use costs nothing and remote relays are covered by donations. https://whipdesk.com https://www.producthunt.com/products/whipdesk
> [zh] **WhipDesk**：一个免费开源、专为在手机浏览器上「看管」编程 agent 设计的远程桌面，无需装 App：智能缩放只推送你正在看的区域，蜂窝网络下代码也清晰；「Auto-Whips」会在 Claude Code、Codex、Gemini CLI、Aider、Copilot CLI、opencode、Cursor Agent 或 Amp 等你回应、完成或崩溃时提醒；还能定时发提示词，比如在凌晨 2 点会话额度重置时自动发一句「continue」，外加一键常用提示词和可定时回放的点击输入宏。端到端加密，`npm install -g whipdesk` 即可安装；作者说局域网使用零成本，远程中继靠捐助维持。
3. **Ottante**: a Mac app from GLP Labs that checks what your agents actually did when Claude Code, Codex, Cursor or Gemini say they are done: it compares each project against the reference it was built from and alerts you only to new differences, so you can mark an intended change once (with a reason) and it stops coming back as an error, and it flags reference updates a project never received. The check itself uses no AI, so it doesn’t eat your subscription, and everything stays local with no account, cloud or telemetry; it never fixes anything itself. Free for the end-of-work check, Pro is €49 one-time. https://glplabs.eu/en/ottante https://www.producthunt.com/products/ottante
> [zh] **Ottante**：GLP Labs 的 Mac 应用，在 Claude Code、Codex、Cursor 或 Gemini 说「做完了」之后核对它们实际做了什么：把每个项目和它所基于的参考模板对比，只提醒新出现的差异；有意为之的改动标记一次（附一句理由）就不会再被当成错误，还会指出项目漏掉的模板更新。检查本身不用 AI、不耗订阅额度，全部在本地，无账号、无云端、无遥测；它从不自己动手修。结束检查功能免费，Pro 版一次性 49 欧元。
4. **Session Vault**: a Claude Code plugin that backs up the sessions you want to keep, since Claude Code stores transcripts only in `~/.claude` on one machine and by default deletes them after 30 days. `/session-vault:save` encrypts the transcript locally with age before upload and `/session-vault:fetch` restores it on another machine where you have copied the key, so the server can’t read conversations. Free for 10 sessions, €3/month for 100 and €10/month for 500, and the server is open source if you’d rather self-host. https://session-vault.dev/ https://news.ycombinator.com/item?id=50655243
> [zh] **Session Vault**：一个 Claude Code 插件，用来备份你想保留的会话——Claude Code 只把对话记录存在单台机器的 `~/.claude` 里，默认 30 天后删除。`/session-vault:save` 在上传前用 age 在本地加密，`/session-vault:fetch` 在拷好密钥的另一台机器上恢复，服务器读不到对话内容。免费存 10 个会话，100 个每月 3 欧元，500 个每月 10 欧元；服务端开源，也可以自己部署。

## 科技新闻
1. **Researcher traces Novita, StreamLake and Ant Digital’s cheap DeepSeek routes on OpenRouter to ByteDance Ark**: Kendell’s post (HN 55 points) finds Ark fingerprints across the three providers: images in requests downloaded from Volcano Engine in Beijing or BytePlus in Singapore, ByteDance-format upstream request IDs on every Ant Digital response, Ark’s tool-call ID format on Novita’s and StreamLake’s V4.1 Flash, ByteDance’s canned refusal on Tiananmen questions, and Ant Digital’s launch price exactly matching BytePlus’s off-peak rate. One V4.1 Flash request could go SiliconFlow → StreamLake → Novita → ByteDance; Novita sent 120–160B tokens a day on these models until losing its ZDR label on November 20, and Ant Digital went from 1B to 35.8B tokens a day on November 21. After the MiniMax canary-URL incident, AtlasCloud, Novita and StreamLake told OpenRouter they had forwarded MiniMax requests to MiniMax, and 16 Novita endpoints have since come off OpenRouter. The author notes an OpenRouter grant helped fund the research. https://kendell.dev/blog/arkwrapper/ https://news.ycombinator.com/item?id=50660273
> [zh] **研究者追查发现，Novita、StreamLake、蚂蚁数科在 OpenRouter 上的低价 DeepSeek 通道实际落到字节方舟**：Kendell 的文章（HN 55 分）在三家身上找到方舟的指纹：请求里的图片由北京火山引擎或新加坡 BytePlus 下载；蚂蚁数科每条响应的上游请求 ID 都是字节格式；Novita 和 StreamLake 的 V4.1 Flash 返回方舟格式的工具调用 ID；问天安门相关问题会得到字节的固定拒答；蚂蚁数科上线价恰好等于 BytePlus 的闲时价。一个 V4.1 Flash 请求可能走 SiliconFlow → StreamLake → Novita → 字节；Novita 在 11 月 20 日失去 ZDR 标签前每天在这些模型上发出 1200–1600 亿 token，蚂蚁数科在 11 月 21 日从每天 10 亿涨到 358 亿。此前 MiniMax 金丝雀 URL 事件后，AtlasCloud、Novita 和 StreamLake 已向 OpenRouter 承认把 MiniMax 请求转发给了 MiniMax，Novita 已有 16 个端点从 OpenRouter 下架。作者注明研究得到了 OpenRouter 的资助。

3. **An AMD-specific llama.cpp patch set nearly doubles prefill on a Radeon R9700**: a devnull.land post (HN 298 points) recommends llama-cpp-rdna-boosts, a small set of AMD patches continually re-applied to pinned llama.cpp commits and shipped as ROCm container images; with Swift-1.5-Qwen3.8-27B (Q6_K_L, MTP on) prefill went from about 700 to 1,300 tokens/s and generation from about 35 to 55 tokens/s. The author contrasts it with vibe-coded engines like Strata that chase speed by changing how the model behaves, such as preferring experts already in VRAM over the ones the router would choose. https://devnull.land/amd-specific-llama-cpp https://news.ycombinator.com/item?id=50657265
> [zh] **一套 AMD 专用的 llama.cpp 补丁让 Radeon R9700 的 prefill 速度接近翻倍**：devnull.land 的文章（HN 298 分）推荐 llama-cpp-rdna-boosts：一小组 AMD 优化补丁，持续重新打到固定版本的 llama.cpp 上，并提供 ROCm 容器镜像；跑 Swift-1.5-Qwen3.8-27B（Q6_K_L，开 MTP）时 prefill 从约 700 升到 1300 token/s，生成从约 35 升到 55 token/s。作者拿它和 Strata 这类 vibe coding 出来的引擎对比：后者靠改变模型行为来提速，比如优先调用已在显存里的专家，而不是路由本该选的专家。

## 中文社区
1. **量子位：TabbyML 让 20 个 AI Agent 组队优化 Quickwit，4 天约 350 次实验后在 ClickBench 数据湖类热查询上超过此前所有公开成绩**：团队分三种角色——只做性能剖析、提出假设的调研员，审每个方案并要求先写「实验契约」（性能目标加正确性、兼容性、内存约束）的 Lead Agent，在隔离环境里实现和测试的验证员；最终只保留 6 项优化，亿级数据 40 条热查询总耗时从 40.5 秒降到 27.9 秒（-31%），geomean 从 403ms 降到 304ms，比 Duckflight 公开成绩快 16%。最值得看的是 E251：一个提速 11%、40 条查询结果全部校验通过的改动，被 Lead Agent 以「悄悄把 IP 比较从字符串序改成数值序、同次数时会改变结果」为由否决。https://www.qbitai.com/2026/11/513053.html https://www.tabbyml.com/blog/beating-clickbench-sota-with-a-team-of-agentic-systems-engineers/
> [en] **QbitAI: TabbyML ran a team of 20 AI agents on Quickwit and, after about 350 experiments in 4 days, beat every prior public ClickBench data-lake hot-query result**: the team has three roles—investigators that only profile and propose hypotheses, a Lead Agent that reviews every plan and requires an “experiment contract” (performance goal plus correctness, compatibility and memory constraints), and verifiers that implement and test in isolated environments; only 6 optimizations survived, cutting total time for 40 hot queries on 100M rows from 40.5s to 27.9s (-31%) and the geomean from 403ms to 304ms, 16% faster than Duckflight’s public result. The standout is E251: a change that sped a query up 11% and passed result checks on all 40 queries was vetoed by the Lead Agent because it quietly switched IP comparison from string to numeric order, which would change results on ties.
