## 有趣用法和干货
1. **Simon Willison: tell Fable 5.2 "This codebase is yours" if you want it to restructure code**: from Anthropic's new Fable 5.2 prompting guide — when the prompt is silent on ownership or calls the code someone else's, the model tends to bolt on and only report nearby problems; with the ownership sentence it merged repeated code in about half of small-task tries versus under a tenth without it, but used ~1.5x output tokens, made unrequested changes (tests, docs) and changed existing behavior in one try in six to ten, so review the diff, not just the summary. Leave it out when the user wants minimal changes; a "no drive-by refactors" rule doesn't fully cancel it. ~2.3k bookmarks. https://x.com/simonw/status/2120029347948220500 | https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2
> [zh] **Simon Willison：想让 Fable 5.2 主动重构，就告诉它「这个代码库归你」**：出自 Anthropic 新版 Fable 5.2 提示指南——提示里不说归属或说是别人的代码时，模型倾向于往现有结构上加东西、只汇报附近问题；加上归属这句话后，小任务里约一半会合并重复代码（不加时不到一成），但输出 token 约 1.5 倍，还会做没要求的改动（测试、文档），每六到十次有一次改变现有功能行为，所以要看 diff 而不只看总结。用户希望少改时别加；「不要顺手重构」的规则也压不住它。约 2.3k 收藏。
2. **More from the Fable 5.2 guide: start at high effort, and paste in a "Finishing work" block if agents stop early**: most of the gain is already at `high` (xhigh/max are uneven and token-hungry); at high and above it thinks before almost every reply, and an "answer directly" line no longer stops thinking at medium+, so lower effort instead. The suggested system-prompt text (diagnose ordinary errors and timeouts, leave deliberate blockers alone) halved sessions that ended with doable work left, for ~30% more output tokens. It also warns that accumulated "never" rules in memory and notes make Fable hold back routine work, and that harnesses editing earlier turns now break preserved thinking. https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2
> [zh] **Fable 5.2 指南的更多要点：先用 high，Agent 提前收工就加一段「Finishing work」**：大部分能力提升在 `high` 档已经拿到（xhigh/max 收益不稳且很费 token）；high 及以上几乎每次回复都先思考，「直接回答、别深思」这类指令在 medium 以上已无效，应改为降档。官方给出的系统提示（普通报错、超时先诊断再继续，刻意设置的阻碍不要绕过）让还有可做工作就结束的会话减半，代价是输出 token 多约 30%。指南还提醒：记忆和笔记里堆积的「绝不」类规则会让 Fable 不敢做常规操作；改写历史轮次的 harness 会让保留的思考块失效。
3. **Jane Street 开源 socratic-tutor Skill：让大模型只提问、不灌输**：开始前用 3–5 个由浅入深的问题摸底，把主题拆成 4–10 个小技能并按 0–5 级画进度条；上课一次只问一个问题，答错不直接给答案，而是换更窄的问题让你自己发现矛盾，错两三次才正面讲，后面还有穿插复习和结业测试。Claude Code 等支持 Skill 的工具直接放进去就能用，普通聊天机器人粘贴内容也行；所在仓库约 3k star。https://x.com/GitHub_Daily/status/2120116776172425268 | https://github.com/janestreet/agent_skills
> [en] **Jane Street open-sources a socratic-tutor Skill that makes the model ask instead of lecture**: it first probes you with 3–5 escalating questions, splits the topic into 4–10 sub-skills rated 0–5 as progress bars, then asks one question at a time; wrong answers get a narrower follow-up so you spot the contradiction yourself, with a direct explanation only after two or three misses, plus spaced review and a final test. Drop it into Claude Code or any Skill-capable tool, or paste it into a regular chatbot; the repo has ~3k stars.
