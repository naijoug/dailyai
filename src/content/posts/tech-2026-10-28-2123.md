## 新产品
1. **Macro: an open-source "operating system" workspace for small teams with shared AI memory**: email (multi-account, Superhuman-style), channels, CRDT markdown docs, Linear-style tasks, canvas, recorded calls, file storage, PR links and CRM in one app, all @-linked in a bidirectional graph that agents can search and act on, with an MCP surface. Built in SolidJS and Rust, dogfooded by a ~15-person team for two years; AGPL-3.0, ~5,200 stars and on GitHub Trending today. https://macro.com [GitHub](https://github.com/macro-inc/macro)
> [zh] **Macro：给小团队用的开源「操作系统」式工作区，带共享 AI 记忆**：把邮件（多账号、类 Superhuman 键盘操作）、频道、基于 CRDT 的 Markdown 文档、类 Linear 任务、白板、录音转写的通话、文件存储、PR 关联和 CRM 放进一个应用，全部用 @ 互相链接成双向图，agent 可以检索并代为操作，另提供 MCP 接口。用 SolidJS 和 Rust 构建，约 15 人团队自用两年；AGPL-3.0，约 5200 star，今日上 GitHub Trending。
2. **OpenLLM: take your AI tokens anywhere**: a unified layer that lets you use your existing subscriptions, API keys and local models inside Codex and other coding agents, or in the ChatGPT app on Mac; when one hits a limit it keeps going on another, and you can start a coding session on your home machine from anywhere. Launching on Product Hunt today (#14, ~76 points). https://openllm.sh [PH](https://www.producthunt.com/products/openllm)
> [zh] **OpenLLM：让你的 AI 额度随处可用**：一个统一接入层，把已有订阅、API key 和本地模型接进 Codex 等 coding agent，或 Mac 上的 ChatGPT 应用里用；某个额度用完会自动切到别的继续跑，还能从任何地方在家里那台机器上开编码会话。今天在 Product Hunt 首发（日榜第 14，约 76 票）。
3. **OpenDsec：按 DeepSeek DSec 论文做的开源自托管 Agent 沙箱平台**：独立项目（不含 DeepSeek 代码），控制面由无状态 apiserver、基于 Raft 的 IAM、watcher 和每节点 edge 组成，组件间 gRPC + mTLS；节点支持 Firecracker microVM、Linux 容器和完整 QEMU VM，microVM 冷启动约 0.1 秒、快照恢复约 55 ms，可暂停成内存快照或 fork 运行中的 VM，网络默认拒绝、按域名/CIDR/端口放行，带 E2B 兼容网关和离线安装；作者实测单节点一批 5120 个 microVM 无失败。AGPL-3.0。https://kernflux.github.io/ [GitHub](https://github.com/Kernflux/opendsec) [V2EX](https://www.v2ex.com/t/1252637)
> [en] **OpenDsec: an open-source, self-hosted agent sandbox platform built from DeepSeek's DSec paper**: an independent project (no DeepSeek code) whose control plane is a stateless apiserver, Raft-backed IAM, a watcher and a per-node edge, talking gRPC + mTLS; nodes run Firecracker microVMs, Linux containers or full QEMU VMs, with ~0.1 s microVM cold starts and ~55 ms snapshot restores, pause-to-memory-snapshot and fork of running VMs, default-deny networking allowlisted by domain/CIDR/port, an E2B-compatible gateway and offline install; the author ran a single batch of 5,120 microVMs on one node without failures. AGPL-3.0.
4. **谷歌 Antigravity SDK 支持本地模型，云端「架构师」+ 本地「构建者」混合编排**：云端主 agent 只凭文件名和任务描述拆分计划、不接触源码，本地 agent 负责复现漏洞、写修复、审补丁和跑回归测试；谷歌演示审计修补三个有漏洞的 Python 模块，约 3400 个 token 中只有 95 个用于云端规划，97.2% 在本地消耗、源码不上云。首发主打经 LiteRT 跑 Gemma 4 26B A4B，也可通过 LocalOpenAIAgentConfig 接 Ollama、LM Studio、vLLM 等 OpenAI 兼容本地服务。https://www.infoq.cn/article/TusFJkx6F151otgzliu2
> [en] **Google's Antigravity SDK adds local models, with a cloud "architect" plus local "builders" hybrid orchestration**: the cloud lead agent splits the plan from file names and task descriptions without seeing source code, while local agents reproduce bugs, propose fixes, review patches and run regression tests; in Google's demo auditing and patching three vulnerable Python modules, only 95 of ~3,400 tokens went to cloud planning, 97.2% were consumed locally and no source was uploaded. It launches around Gemma 4 26B A4B via LiteRT, and also supports OpenAI-compatible local servers such as Ollama, LM Studio and vLLM through LocalOpenAIAgentConfig.

## 科技新闻
1. **Apple's git still trusts the compromised eMudhra certificates**: Apple was notified on Oct 17, but as of Oct 28 the git, curl and python3 it ships with macOS still trust the compromised intermediates, and macOS 27.2 (Oct 26) even undid the manual workaround — so anyone on the network path can tamper with https:// clones and pulls and intercept tokens. The page gives a one-line check (`git ls-remote https://git-emudhra.we-have-a-problem.com/check.git`; a certificate error means you're safe) and an end-to-end demo impersonating GitHub; Apple has also published a support note. https://emudhra.we-have-a-problem.com/apple.html [HN](https://news.ycombinator.com/item?id=50271640)
> [zh] **苹果自带的 git 仍信任已被攻破的 eMudhra 证书**：苹果 10 月 17 日就收到通知，但截至 10 月 28 日，macOS 自带的 git、curl、python3 仍信任这些被攻破的中间证书，10 月 26 日发布的 macOS 27.2 甚至撤销了用户手动做的规避措施——网络路径上的任何人都能篡改 https:// 的 clone/pull 并截获 token。页面给出一行自检命令（`git ls-remote https://git-emudhra.we-have-a-problem.com/check.git`，报证书错误即安全）和冒充 GitHub 的完整演示；苹果也发了支持文档。
2. **Pre-boot code-execution flaw in EDK II threatens most of the world's servers**: CVE-2026-97631 (9.5) is a memory-corruption bug in the ICMP handling of TianoCore EDK II's PXE network boot, the reference code behind AMI, Insyde, Phoenix and Microsoft's Project Mu firmware; it runs code before Secure Boot and the TPM chain of trust take over. Found by Anthropic's Alex Matrosov and Google's Dan Holmes for a January disclosure, it leaked early when AMI published a fix PR, so patch code is now public while firmware updates will take a long time to reach devices. https://arstechnica.com/security/2026/10/code-execution-flaw-in-uefi-firmware-threatens-most-servers-on-planet-earth/ [HN](https://news.ycombinator.com/item?id=50265393)
> [zh] **EDK II 预启动代码执行漏洞波及全球多数服务器**：CVE-2026-97631（9.5 分）是 TianoCore EDK II 中 PXE 网络启动处理 ICMP 时的内存破坏漏洞，AMI、Insyde、Phoenix 和微软 Project Mu 的固件都基于这套参考代码；攻击代码能在 Secure Boot 和 TPM 信任链生效前运行。漏洞由 Anthropic 的 Alex Matrosov 和谷歌的 Dan Holmes 发现，原定 1 月协调披露，却因 AMI 提前公开修复 PR 而泄露，补丁代码已公开，而固件更新要很久才能覆盖到设备。
3. **Python's experimental JIT is being removed**: the JIT Brandt Bucher added to CPython in 2024 (3.13) is on its way out — after the steering council paused work in June pending a standards-track PEP with maintenance, compatibility and success-metric commitments, the maintainers wrote PEP 836 ("JIT Go Brrr") but have now withdrawn it after months of discussion, effectively ending the project for now. https://lwn.net/SubscriberLink/1102102/0c00e4d550f25f8c/ [HN](https://news.ycombinator.com/item?id=50257419)
> [zh] **Python 的实验性 JIT 将被移除**：Brandt Bucher 2024 年加入 CPython（3.13）的 JIT 即将下线——指导委员会 6 月叫停主分支上的开发，要求先提交写明维护、兼容性和成功指标的标准类 PEP；维护者为此写了 PEP 836（「JIT Go Brrr」），但经过数月讨论后已撤回，这个项目目前基本告一段落。
4. **Git for the US Code: Lexifina versions federal statutes like source code**: the post shows why "which law wrote this sentence and when did it take effect" is buried in prose notes (e.g. the small-business debtor limit in 11 USC § 1182(1) changing four times since 2019) and cites a TU Munich study where a model got 24% of post-cutoff statute questions right alone vs 87% with the right historical text retrieved — arguing legal RAG needs blame-style lineage with effective dates. https://lexifina.com/blog/git-for-the-us-code [HN](https://news.ycombinator.com/item?id=50268380)
> [zh] **给美国法典做 Git：Lexifina 像管理源码一样给联邦法条做版本管理**：文章说明「哪部法律写了这句、何时生效」只散落在文字注释里（例如 11 USC § 1182(1) 的小企业债务人上限自 2019 年起变了四次），并引用慕尼黑工业大学的研究：模型单独回答训练截止后的法条问题正确率 24%，检索到对应历史条文后升到 87%——主张法律 RAG 需要带生效日期、类似 git blame 的条文沿革。
