## 新产品
1. **Firecrawl Local**: Firecrawl rebuilt its open-source repo so agents can scrape from your own machine: a single Rust binary (`cargo install firecrawl-local`) that scrapes, crawls and maps sites into clean markdown, parses PDFs and Office docs locally, serves the Firecrawl v2 API on localhost so existing Firecrawl code runs unchanged, and `firecrawl-local init` registers it as an MCP server in Claude Code, Cursor, Windsurf, Gemini CLI and Codex. Firecrawl claims a 37x faster scrape primitive than self-hosting and 230x less memory (11 MB idle); search and pages that refuse your machine still go to Firecrawl Cloud, which can be turned off. The launch post drew about 3,900 likes and 5,500 bookmarks. https://www.firecrawl.dev [GitHub](https://github.com/firecrawl/firecrawl) [X](https://x.com/firecrawl/status/2123096169630912637)
> [zh] **Firecrawl Local**：Firecrawl 重写了开源仓库，让 Agent 能在本机抓网页：一个 Rust 单文件程序（`cargo install firecrawl-local`），可以抓取、爬取和列出整站页面并转成干净的 markdown，PDF 和 Office 文档也在本地解析；它在 localhost 上提供 Firecrawl v2 API，现有 Firecrawl 代码无需改动，`firecrawl-local init` 会把它注册为 Claude Code、Cursor、Windsurf、Gemini CLI 和 Codex 的 MCP 服务器。官方称抓取原语比自托管快 37 倍、内存少 230 倍（空闲 11 MB）；搜索和拒绝本机访问的页面仍走 Firecrawl Cloud，可关闭。发布帖约 3900 赞、5500 收藏。
2. **Stitch Loop**: a new Google Labs experiment, a long-running product agent that connects to GitHub and your product context (logs, user behavior, feedback) through 180+ integrations, custom MCP servers or CLI uploads, then runs evergreen loops: it surfaces evidence-backed suggestions, offers solutions with tradeoffs, writes code in an isolated cloud sandbox and opens a PR for your approval, and keeps watching live metrics after the goal is met. Built-in loops cover security (Gemini 4 Carbon plus DeepMind’s CodeMender), latency and accessibility; coding agents like Antigravity can pull its context via the Stitch CLI and MCP, and there is an @stitch Slack integration. The waitlist is open globally, with priority for eligible Google AI Ultra users. https://stitch.google.com/loop/waitlist [Google 博客](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-loop/)
> [zh] **Stitch Loop**：Google Labs 新实验，一个长期运行的产品 Agent：通过 180 多个集成、自定义 MCP 服务器或 CLI 上传接入 GitHub 和产品上下文（日志、用户行为、反馈），然后持续跑「循环」：给出有证据支撑的建议和带取舍的方案，在隔离的云沙盒里写代码并开 PR 等你批准，达成目标后继续盯着线上指标。内置安全（Gemini 4 Carbon 加 DeepMind 的 CodeMender）、延迟和无障碍三个循环；Antigravity 等编码 Agent 可以通过 Stitch CLI 和 MCP 拉取它的产品上下文，Slack 里可用 @stitch。全球开放候补名单，符合条件的 Google AI Ultra 用户优先。

Snap says a full Web Lens game can go from idea to published in a day; Lenses go through the usual review, Lens+ Payouts apply (Snap paid $1.8M to creators last month), and it runs on Mac, Windows and Linux. https://easylens.snapchat.com/cli [Snap 公告](https://newsroom.snap.com/introducing-easy-lens-cli) [TechCrunch](https://techcrunch.com/2026/11/18/snapchat-now-lets-developers-build-ar-lenses-with-ai-coding-assistants-like-claude-code-and-cursor/)

4. **Perplexity Context API**: reads up to 10 URLs per call and returns clean markdown, HTML, links and snippets per page; Perplexity reports usable content for 92.3% of URLs, 87.9% fact recall and 80.3% content precision at $1 per 1,000 URLs fetched, and Aravind Srinivas says it can be used inside any agent harness. https://www.perplexity.ai/hub/blog/context-api-extracts-full-context-from-any-web-page [X](https://x.com/perplexitydevs/status/2123085051013546406)
> [zh] **Perplexity Context API**：每次调用最多读取 10 个 URL，按页返回干净的 markdown、HTML、链接和摘要片段；Perplexity 给出的数据是 92.3% 的 URL 能拿到可用内容、事实召回 87.9%、内容精度 80.3%，价格为每抓取 1000 个 URL 1 美元。Aravind Srinivas 称可在任何 Agent 框架里使用。

## 科技新闻
1. **Ruby2Shell: a one-byte heap overflow in Ruby reachable pre-auth in default Rails and classic Sinatra**: upcasing “ß” in single-byte encodings such as ISO-8859-1 and Windows-1252 writes “SS” but bounds-checks only one byte, a bug present since Ruby 2.4.0 and reached by `upcase`, `swapcase`, `downcase(:fold)` and `casecmp?` (UTF-8 is not affected). Ruby released 4.0.10, 3.4.13 and 3.3.14 fixing it and six other Regexp/case-conversion flaws, saying it knows of PoCs that reach RCE in some scenarios; Ruby 3.2 and older are EOL with no fix, and upgrading Rails does nothing because the bug is in the interpreter. Veria Labs lists GitLab 19.6.0, GitHub Enterprise Server 3.22.5 and Chatwoot 4.20.0 as bundling affected Rubies and will publish its PoC in about a week; Equixly notes the Ruby advisory credits Stephan Lipp (Ada Logics) and Anthropic. https://verialabs.com/ruby2shell/ [Ruby 公告](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/) [HN](https://news.ycombinator.com/item?id=50556287)
> [zh] **Ruby2Shell：Ruby 单字节堆溢出，Rails 和经典 Sinatra 默认配置下免认证可达**：在 ISO-8859-1、Windows-1252 等单字节编码里把「ß」转大写会写出「SS」两个字节，但只检查了一个字节的边界；这个 bug 从 Ruby 2.4.0 起就存在，`upcase`、`swapcase`、`downcase(:fold)` 和 `casecmp?` 都会触发（UTF-8 不受影响）。Ruby 发布 4.0.10、3.4.13 和 3.3.14，同时修复另外六个正则和大小写转换漏洞，称已知有 PoC 能在部分场景下实现远程代码执行；3.2 及更早版本已停止维护、不会修复，而且问题在解释器里，升级 Rails 没用。Veria Labs 列出 GitLab 19.6.0、GitHub Enterprise Server 3.22.5 和 Chatwoot 4.20.0 仍内置受影响的 Ruby，约一周后公开 PoC；Equixly 指出 Ruby 公告把发现者记为 Stephan Lipp（Ada Logics）和 Anthropic。
