## 新产品
1. **Workflow SDK 5.8**: Vercel rebuilt the execution engine behind its durable-workflow SDK around speculative execution of retryable steps. Its benchmarks show p75 step-to-step overhead falling from 85 ms to 7 ms versus 5.2, a 256-step fan-out adding 2.5 s of overhead instead of 13.5 s, and a five-turn agent loop with durable token streaming and tool calls adding 0.9 s instead of 3.0 s. Steps must be idempotent (pass `stepId` as the idempotency key) or set `maxRetries = 0` to opt out; `WORKFLOW_SPEC_VERSION=8` keeps the old engine. The New Stack frames it with Guillermo Rauch’s view that as models get smarter “the harness itself blurs away” and agent execution infrastructure matters more. https://workflow-sdk.dev https://vercel.com/changelog/workflows-speculative-execution https://thenewstack.io/vercel-workflow-sdk-harness/
> [zh] **Workflow SDK 5.8**：Vercel 围绕「可重试步骤的推测执行」重写了持久化工作流 SDK 的执行引擎。官方基准显示，相比 5.2，p75 步骤间开销从 85 毫秒降到 7 毫秒，256 个并行步骤的额外开销从 13.5 秒降到 2.5 秒，一个带持久化 token 流和工具调用的五轮 Agent 循环额外开销从 3.0 秒降到 0.9 秒。步骤需要幂等（把 `stepId` 当幂等键），否则设 `maxRetries = 0` 退出推测执行；设 `WORKFLOW_SPEC_VERSION=8` 可保留旧引擎。The New Stack 把它和 Guillermo Rauch 的观点放在一起：模型越聪明，「harness 本身会逐渐隐形」，执行 Agent 的基础设施会更重要。
2. **AWS Nitro Sandboxes**: lightweight VMs on the Nitro hypervisor that give each EKS pod, ECS task or VM, including AI agents running LLM-generated code, its own hardware isolation boundary inside a shared EC2 instance, at no extra charge in all commercial regions. On EKS Auto Mode it is a one-line `runtimeClassName: isolated-sandbox` (or `confidential-sandbox`) change with no image rebuild; confidential mode keeps the parent instance from seeing inside and releases KMS secrets only after attestation, which AWS says lets a model vendor ship closed weights into a customer account. In a New Stack interview, AWS’s Mike Stefaniak says security and identity are what still keep most teams from running agents in production. https://aws.amazon.com/about-aws/whats-new/2026/11/nitro-sandboxes-eks-ecs-ec2/ https://thenewstack.io/aws-nitro-sandboxes-agents/
> [zh] **AWS Nitro Sandboxes**：基于 Nitro 虚拟机管理程序的轻量虚拟机，让共享 EC2 实例里的每个 EKS Pod、ECS 任务或虚拟机（包括运行大模型生成代码的 AI Agent）都有独立的硬件隔离边界，所有商业区域可用且不额外收费。在 EKS Auto Mode 上只需把 `runtimeClassName` 设为 `isolated-sandbox`（或 `confidential-sandbox`），不用重建镜像；机密模式下宿主实例看不到沙箱内部，KMS 密钥只在通过证明后才发放，AWS 称模型厂商可以借此把闭源权重部署到客户账号里。AWS 的 Mike Stefaniak 在 The New Stack 采访中说，安全和身份问题仍是多数团队不敢把 Agent 放进生产的主要原因。
3. **SessionGraph**: a local tool (`npx sessiongraph`) that indexes your coding-agent session history across about 60 harnesses, including Claude Code, Codex, Cursor, OpenCode, Antigravity, Gemini CLI, Hermes Agent and WorkBuddy, and shows it as an interactive 3D graph; it also exposes the index over MCP (`search_sessions`) and a REST API so agents can pull context from old sessions. On HN (33 points) the author says he stopped editing files himself in 2026 and now thinks in sessions; one commenter found it only detected Claude and missed OpenCode, and another asked what value there is in old sessions once the code and commits exist. https://sessiongraph.ai/ https://news.ycombinator.com/item?id=50671651
> [zh] **SessionGraph**：一个本地工具（`npx sessiongraph`），把约 60 种编程 Agent（包括 Claude Code、Codex、Cursor、OpenCode、Antigravity、Gemini CLI、Hermes Agent、WorkBuddy 等）的会话记录建成索引，并以可交互的 3D 图展示；索引还通过 MCP（`search_sessions`）和 REST API 开放，让 Agent 能从旧会话里找回上下文。HN（33 分）上作者说自己 2026 年已经完全不亲手改文件，脑子里只按「会话」思考；有评论说它只识别出 Claude、漏掉了 OpenCode 的会话，也有人问代码和提交记录都在了，旧会话还有什么价值。
4. **Tesseracted LLM-in-Wasm**: a 52 KB WebAssembly engine, written in Zig and ported from the pure-assembly llm.asm, that runs Qwen3.5-2B/0.8B and Qwen3-1.7B/0.6B entirely on the CPU in a browser tab, using Unsloth’s Q4_K_M GGUF weights as published, with no GPU code or inference API. Integer kernels work directly on the packed 4- and 6-bit weights, and a `/python` command has the model write code that runs in a second offline CPython-in-Wasm sandbox for arithmetic, dates and small charts; the author says outputs match PyTorch on the same weights to about four decimal places. https://tesseracted.com/experiments-llm-os/ https://news.ycombinator.com/item?id=50673018
> [zh] **Tesseracted 浏览器内 Wasm 大模型**：一个只有 52 KB 的 WebAssembly 推理引擎，用 Zig 编写、移植自纯汇编的 llm.asm，在浏览器标签页里只用 CPU 跑 Qwen3.5-2B/0.8B 和 Qwen3-1.7B/0.6B，直接使用 Unsloth 发布的 Q4_K_M GGUF 权重，没有 GPU 代码也不调推理 API。整数算子直接在打包的 4/6 位权重上计算；输入 `/python` 会让模型写代码，交给另一个离线的 CPython-Wasm 沙箱执行，用来算数、算日期和画小图；作者称输出与 PyTorch 跑同样权重的结果在小数点后约 4 位一致。
5. **Prospero**: Chris Wellons (skeeto) released a native, public-domain AI coding harness for Windows, macOS and Linux built with Dear ImGui: a single C++ executable (about 5 MB on Windows per HN) that speaks the OpenAI Chat Completions and Anthropic Messages APIs, works with llama.cpp, vLLM and LiteLLM, supports skills, MCP servers and web search, and can control the desktop to develop and test GUI apps. It renders passively so it idles at no cost, can run headless or on another machine over ssh, and the author says the engine runs on systems “a quarter century old”, even Windows XP. https://github.com/skeeto/prospero https://news.ycombinator.com/item?id=50671275
> [zh] **Prospero**：Chris Wellons（skeeto）发布了一个用 Dear ImGui 写的原生 AI 编程 harness，公有领域授权，支持 Windows、macOS 和 Linux：单个 C++ 可执行文件（HN 上有人说 Windows 版约 5 MB），支持 OpenAI Chat Completions 和 Anthropic Messages 接口，可接 llama.cpp、vLLM、LiteLLM，支持技能、MCP 服务器和网页搜索，还能控制桌面来开发和测试 GUI 程序。界面被动渲染、空闲时不占资源，可以无界面运行或通过 ssh 跑在另一台机器上，作者称引擎能跑在「25 年前」的系统上，甚至 Windows XP。

2. **Michael Nielsen takes down “Neural Networks and Deep Learning”**: the author of the widely used free book replaced the site with a note saying that when he wrote it (2011–2015) he expected AGI to be decades away, but “with the extraordinarily reckless behaviour of the frontier labs” systems raced ahead too fast, and he no longer wants to help train people to contribute to this work. He argues the deeper risk is ASI unleashing cheap, catastrophic technologies faster than institutions can build defences, likening it to the matchstick versus the cost of fire defence. On HN (411 points) many posted Wayback Machine links, and one top comment asked whether the knowledge now lives only in model weights. https://neuralnetworksanddeeplearning.com/ https://news.ycombinator.com/item?id=50670757
