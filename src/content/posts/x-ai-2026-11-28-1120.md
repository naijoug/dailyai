## AI 热点
1. **Gemini 4 Neon debuts on the Epoch Capabilities Index in a near three-way tie at the top**: Epoch’s published ECI scores put Claude Fable 5.2 at 173.2, Gemini 4 Neon at 171.8 and GPT-6.2 Astra at 171.6, with 90% intervals that almost fully overlap (168–176); Gemini 4 Carbon is next at 169.1, then Claude Opus 5.5 and GPT-6.1 Sol at about 168.5. The surprise is GPT-6.2 Sol at 162.6, roughly 18th and about six points below the older 6.1 Sol, though posts note it has only six benchmarks so far. One reply warns that ECI aggregates benchmarks labs know about and partly train against, so a tight cluster at the top may partly be Goodhart. https://x.com/gadi_neelesh/status/2126412886700667311 https://epoch.ai/benchmarks/eci
> [zh] **Gemini 4 Neon 登上 Epoch 综合能力指数，头部几乎三家并列**：Epoch 公布的 ECI 分数里，Claude Fable 5.2 为 173.2、Gemini 4 Neon 为 171.8、GPT-6.2 Astra 为 171.6，三者 90% 置信区间几乎完全重叠（168–176）；其后是 Gemini 4 Carbon 169.1，Claude Opus 5.5 和 GPT-6.1 Sol 都在 168.5 左右。意外的是 GPT-6.2 Sol 只有 162.6，约排第 18，比上一代 6.1 Sol 低约 6 分，不过有帖子指出它目前只测了 6 项基准。也有回复提醒，ECI 汇总的是各家都知道、并在一定程度上针对性训练过的基准，头部挤成一团可能部分是古德哈特效应。
2. **“Google now sells distillation” went viral, but the docs only allow GLM 5.2 as the teacher**: Hugging Face CEO Clem Delangue posted a screenshot of Google Cloud’s open-model tuning page, calling distillation “good and healthy” and one of the few checks on concentration of power (4.9k likes, 1k bookmarks). Replies that opened the “supported models” tab found the only supported teacher is Z.ai’s GLM 5.2 MaaS, with Qwen 3 (4B–32B) and Gemma 3 (1B–27B) as students; Gemini is not offered as a teacher there, and you pay for both tuning and the teacher’s API calls. Other posts point out that Gemini-to-Gemini distillation is a separate early-access service and that the Gemini API terms still ban using outputs to build competing models. https://x.com/ClementDelangue/status/2126322165364719677 https://x.com/andyreynolds/status/2126406397038604583 https://cloud.google.com/vertex-ai/generative-ai/docs/models/open-model-tuning
> [zh] **「谷歌开卖蒸馏」刷屏，但文档里老师模型只有 GLM 5.2**：Hugging Face CEO Clem Delangue 晒出 Google Cloud 开放模型微调页面截图，称蒸馏「健康有益」，是少数能限制权力过度集中的手段之一（4.9k 赞、1k 收藏）。点开「支持的模型」一栏的回复发现，唯一支持的老师模型是智谱的 GLM 5.2 MaaS，学生模型是 Qwen 3（4B–32B）和 Gemma 3（1B–27B），那里并不提供 Gemini 作老师，而且微调和老师模型调用都要另外付费。也有帖子指出，Gemini 蒸馏到 Gemini 是另一项抢先体验服务，Gemini API 条款仍然禁止用其输出训练竞品模型。
3. **Antigravity is hiding an agent builder and plugin “Bundles”**: TestingCatalog found an unreleased UI in Antigravity for creating AI agents by setting a name, icon and goal, alongside an earlier hidden way to create agents from a prompt (819 likes); it argues that with Antigravity becoming Google’s main AI app and Google behind on personal agents, these could land there soon. A second find: “Bundles”, described as “curated sets of plugins for common workflows and roles” such as finance or legal, similar to what Claude offers. Both are still hidden. https://x.com/testingcatalog/status/2126306271892475950 https://x.com/testingcatalog/status/2126331794379215080
> [zh] **Antigravity 藏着智能体创建器和插件「合集」**：TestingCatalog 在 Antigravity 里发现一个未上线的界面，可以设定名称、图标和目标来创建 AI 智能体，此前还发现过一个用提示词创建智能体的隐藏入口（819 赞）；他认为 Antigravity 正在成为谷歌的主力 AI 应用，而谷歌在个人智能体上明显落后，这些功能可能很快上线。另一个发现是「Bundles」，官方描述为「面向常见工作流和角色的精选插件合集」，比如财务、法务，Claude 也有类似功能。两者目前都还隐藏着。
4. **Paper: agent teams only beat solo agents when members hold different information**: “Recursive Collective Intelligence” (arXiv, Nov 24), highlighted by Elvis Saravia (213 bookmarks), grades multi-agent groups against compute-matched baselines: one agent, a majority vote of independent agents, and pass@n. Most of the usual team gain is explained by spending more tokens; teams clear the hardest bar only when facts are split across agents and passed around, by about a third at 27B. Identical 27B agents spontaneously formed hubs and gained 18 points, and groups that trained the next generation on their own verified outputs, with no labels, kept improving for several generations on PlanBench, HiddenBench and Hanabi. https://x.com/omarsar0/status/2126334991768711575 https://arxiv.org/abs/2611.32606
> [zh] **论文：只有成员掌握不同信息时，智能体团队才胜过单个智能体**：Elvis Saravia 推荐的论文《Recursive Collective Intelligence》（arXiv，11 月 24 日，213 收藏）用算力对齐的基线来评判多智能体团队：单个智能体、独立智能体多数投票、以及 pass@n。常见的团队增益大部分只是多花了 token；只有把事实拆给不同智能体并互相传递时，团队才越过最难的一档，27B 模型上高出约三分之一。完全相同的 27B 智能体会自发形成枢纽节点，准确率提高 18 个百分点；团队用自己验证过的输出（无标签）训练下一代，在 PlanBench、HiddenBench 和 Hanabi 上连续几代都在进步。

## 有趣用法和干货
1. **数字生命卡兹克分享一条 /goal 提示词：让 Agent 持续给整个代码库「降熵」**：这条长提示词（3.8k 赞、8k 收藏）要求 Agent 假设「今天是产品诞生的第一天」但已知全部真实需求，按 7 条工程属性（单一事实来源、标准实现唯一、深模块、高内聚低耦合、改动局部化、删除优先于堆积、可强制执行的架构约束）逐项治理 UI、领域模型、API、状态、配置、错误处理、权限等；循环流程是扫描→找偏离→提多个方案选总复杂度最低→建行为基线→整批迁移并删除旧实现→独立复审→加防回归检查，并用「Deletion Test」检验每层抽象。还规定在隔离的 Git worktree 里执行、每批独立 commit、维护进度文件和架构决策记录，遇到产品决策或破坏性迁移就记为待确认、继续做其他任务。https://x.com/Khazix0918/status/2126324185626734795
> [en] **Khazix shares a /goal prompt that keeps an agent “reducing entropy” across a whole codebase**: the long prompt (3.8k likes, 8k bookmarks) asks the agent to imagine “today is the product’s first day” while knowing every real requirement, then govern UI, domain models, APIs, state, config, error handling, auth and more against seven properties (single source of truth, one canonical implementation, deep modules, high cohesion/low coupling, locality of change, deletion over accumulation, enforceable architecture). The loop is scan → find deviations → propose several plans and pick the lowest total complexity → set a behavior baseline → migrate a full batch and delete the old implementation → independent review → add regression guards, with a “Deletion Test” for every abstraction layer. It runs in an isolated Git worktree with one commit per batch, keeps a progress file and decision records, and parks product decisions or breaking migrations as “to confirm” while continuing other work.
2. **Philipp Schmid’s 16-line deep-research skill turns coding agents into researchers**: Google’s Phil Schmid released an experimental skill for Gemini 4 Neon (2.2k likes, 2.3k bookmarks) built on five rules: scope simple questions directly and broad ones in 3–5 angles; run parallel search or browser subagents with an 8–12 step cap; use primary filings and PDFs rather than search snippets; cancel stalled workers and allow at most one follow-up; report with a two-sentence summary, inline links and noted conflicts. He says it was preferred over 90% of the time versus no skill in hundreds of blind evals. Install with `npx skills add google-gemini/demolab --skill deep-research`. https://x.com/_philschmid/status/2126312943520243885 https://x.com/_philschmid/status/2126312946389377447 https://github.com/google-gemini/demolab
> [zh] **Philipp Schmid 的 16 行深度调研技能，把编程 Agent 变成研究员**：谷歌的 Phil Schmid 发布了一个面向 Gemini 4 Neon 的实验性技能（2.2k 赞、2.3k 收藏），核心是五条规则：简单问题直接答，宽泛问题拆成 3–5 个角度；并行派出搜索或浏览器子 Agent，每个最多 8–12 步；只用一手文件和 PDF，不用搜索摘要；卡住的子任务直接取消，最多追问一次；报告用两句话总结、行内链接并标出相互矛盾之处。他说在数百次盲评里，有这个技能的结果九成以上胜出。安装命令：`npx skills add google-gemini/demolab --skill deep-research`。
3. **一句话让 Antigravity 像 Claude、Codex 那样边干边汇报**：卡兹克说很多人受不了 Antigravity 闷头干两三个小时不吭声、最后突然给结论（1k 赞、1.1k 收藏），解决办法是在 GEMINI.md 里加一句：「干活时边做边说：动手前一句话说要做什么；之后不用每步都说，有发现、换方向、卡住，或者连着干了四五步时再说一句，沉默不行。」https://x.com/Khazix0918/status/2126294658431201385
> [en] **One line makes Antigravity narrate its work like Claude or Codex**: Khazix says many people dislike how Antigravity works silently for two or three hours and then drops a conclusion (1k likes, 1.1k bookmarks); the fix is one line in GEMINI.md: “Narrate as you work: say in one sentence what you’re about to do; no need to report every step, but speak up when you find something, change direction, get stuck, or have done four or five steps in a row. Silence is not OK.”
4. **Check coupling with an axiomatic-design prompt in Claude Code**: Vox suggests asking Claude Code to “extract this project’s functional requirements, run an MIT axiomatic design analysis, then tell me whether the design matrix is lower-triangular” (327 bookmarks). Only a lower-triangular or diagonal matrix means modules are not coupled; otherwise ask for refactoring suggestions until it is, so fixing one bug stops breaking ten others, and a diagonal matrix makes every module swappable. https://x.com/Voxyz_ai/status/2126300017224974772
> [zh] **在 Claude Code 里用公理化设计提示词检查耦合**：Vox 建议让 Claude Code「提取项目的功能需求，做一次 MIT 公理化设计分析，再告诉我设计矩阵是不是下三角」（327 收藏）。只有下三角或对角矩阵才说明模块之间没有耦合；不是的话就让它给重构建议，直到达标，这样修一个 bug 不会连带弄坏十个地方，对角矩阵更是让每个模块都能随时替换。
