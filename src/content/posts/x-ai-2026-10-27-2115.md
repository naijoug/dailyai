## AI 热点
1. **宝玉：Anthropic 也放出 AI 推翻指数时间假设（ETH）的论文，署名作者只有 Claude**：就在 OpenAI 宣布同一结果的同一天，Anthropic 在 GitHub 的 formal-math 仓库发布了一个 3-SAT 的 2^o(n) 确定性算法（实际可计数 #3-SAT），附 AI 写的 Lean 4 形式化证明；论文称核心算法是 10 月 16 日由内部研究版 Claude 找到的，用了 1400 万输出 token、没有人类输入，研究员只协助改进了表述。巧的是 OpenAI 也说自家模型是 10 月 16 日找到证明的；README 还称 Claude Opus 5.5 高档位能从一段浓缩描述重新推出这一反驳。Anthropic 研究员的原帖 2000+ 赞。https://x.com/dotey/status/2114952872458633296 | https://github.com/anthropics/formal-math/tree/main/eth
> [en] **Baoyu: Anthropic also posts a paper refuting the Exponential Time Hypothesis (ETH), with Claude as sole author**: on the same day OpenAI announced the same result, Anthropic published a deterministic 2^o(n) algorithm for 3-SAT (it actually counts #3-SAT) in its formal-math GitHub repo, with an AI-written Lean 4 formalization; the paper says the core algorithm was found on October 16 by an internal research Claude model using 14M output tokens and no human input, with researchers only helping improve the presentation. Notably, OpenAI also says its model found the proof on October 16; the README adds that Claude Opus 5.5 at high effort can rederive the refutation from a condensed description. The Anthropic researcher's original post has 2,000+ likes.
2. **百度开源 Unlimited OCR 2：几百页长文档整本解析，注意力开销尽量不随页数涨**：3B/A0.5B 的 MoE 模型，用 SR-SWA 稀疏参考滑窗注意力把文本–视觉交互压进固定大小的工作参考集（README 举例 512 token），再按页分块解码、页边界重叠复用 KV；作者称百页量级逐步速度约为全注意力的 7 倍、v1 的 5.6 倍，v1 原本约卡在 40 页。Berryxia 实测整套 3623 页《哈利·波特》不切分 1.5 小时读完、1665 页《平凡的世界》40 分钟导出 txt。权重已上 GitHub 和 Hugging Face。https://x.com/shao__meng/status/2115039161308852364 | https://huggingface.co/baidu/Unlimited-OCR-2
> [en] **Baidu open-sources Unlimited OCR 2: parse documents of hundreds of pages in one go, with attention cost kept roughly flat as pages grow**: a 3B/A0.5B MoE model that uses SR-SWA (sparse reference sliding-window attention) to squeeze text–vision interaction into a fixed-size working reference set (512 tokens in the README example), plus page-chunked decoding that overlaps page boundaries and reuses the KV tail; the authors claim ~7x faster per step than full attention and 5.6x faster than v1 at around 100 pages, where v1 topped out at about 40 pages. Berryxia's test read all 3,623 pages of Harry Potter unsplit in 1.5 hours and exported the 1,665-page Ordinary World to txt in 40 minutes. Weights are on GitHub and Hugging Face.

## 有趣用法和干货
1. **Addy Osmani: before adding another subagent, ask what problem it solves**: a bloated system prompt is often the real issue, and skills plus tool search can fix that without splitting context across agents. Keep a subagent only when work is parallel, needs fresh context, or one agent truly can't pick the right tools; otherwise fold it into the main loop, turn its prompt into a skill, run your evals and keep whatever wins. He points to Anthropic's write-up on when to fold subagents back into the main agent loop. 680+ likes, 560+ bookmarks. https://x.com/addyosmani/status/2114967833708732607 | https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop
> [zh] **Addy Osmani：再加一个子 Agent 之前，先问它在解决什么问题**：真正的问题往往是系统提示词太臃肿，用 Skills 加工具搜索就能解决，不必把上下文拆到多个 Agent。只有在任务可并行、需要全新上下文、或单个 Agent 实在选不对工具时才保留子 Agent；否则把它并回主循环，把它的提示词改成 skill，跑评测，留下表现更好的方案。他推荐了 Anthropic 关于何时把子 Agent 合回主循环的文章。680+ 赞、560+ 收藏。
2. **meng shao 解读 Matt Pocock 44 分钟访谈：说清你在乎什么，让代码库配得上 Agent**：Pocock 试了几个月 Spec 驱动开发，规格越写越细、代码质量反而一路下滑，结论是代码本身就是 Agent 的工作环境；他常用 Claude Code + Opus 5.5，effort 只开 medium，认为给 Agent 开浏览器看截图往往比换新模型更赚；高频 skill「grill me」让 Agent 不停追问挖出真实需求；起步按「信任阶梯」先学刹车再踩油门，先交给琐碎、可衡量、改错成本低的活。https://x.com/shao__meng/status/2115036397799428313 | https://www.youtube.com/watch?v=Z8lf5oWKfj0
> [en] **meng shao breaks down Matt Pocock's 44-minute interview: say what you care about, and make your codebase worthy of agents**: after months of spec-driven development, Pocock found that ever more detailed specs made code quality steadily worse, concluding the code itself is the agent's working environment; he uses Claude Code + Opus 5.5 at medium effort only, and finds giving agents a browser and screenshots often pays off more than a newer model; his go-to "grill me" skill has the agent keep questioning to surface real requirements; to start, climb the "trust ladder" by learning the brakes before the gas, handing off trivial, measurable, cheap-to-fix tasks first.
3. **skill-diet：用评测保证「更瘦但不更差」的 Skill 减重 meta-skill**：它把臃肿的 SKILL.md 压薄并校对工具命令是否过时，只有在「旧 skill / 新 skill / 无 skill」同任务评测里不输时才保留瘦版；之后每次增补先过门槛，体积比上次 diet 涨约 10% 就再瘦一轮，并按「description → SKILL.md → references → 工具 help → 报错」分层放事实。作者 @nicopreme 称在真实 skill 上可砍 70–80% token，还测出了文档里已失效的命令。https://x.com/shao__meng/status/2115020426514469165 | https://github.com/nicobailon/skill-diet
> [en] **skill-diet: a meta-skill that slims Skills while evals guarantee "leaner but not worse"**: it trims bloated SKILL.md files and checks whether tool commands are outdated, keeping the lean version only if it doesn't lose in same-task evals of old skill / new skill / no skill; later additions must pass a gate, and another diet runs once size grows ~10% past the last one, with facts layered as description → SKILL.md → references → tool help → error messages. Author @nicopreme says it cut 70–80% of tokens on real skills and caught commands in docs that no longer worked.
4. **Matt Pocock: a GOATed example of why domain knowledge matters**: working on his video editor, he knew certain consonants can mess with silence detection and told his agent so; the single word "fricative" was enough for it to bust out full IPA and brainstorm which consonants are most troublesome. In a follow-up he says agents shine on tasks where they have 100% of the data, can run experiments, verify independently and hill-climb, where his trust is maxed out. 670+ likes. https://x.com/mattpocockuk/status/2115023694942662985
> [zh] **Matt Pocock：领域知识有多重要的绝佳例子**：做视频编辑器时，他知道某些辅音会干扰静音检测，就告诉了 Agent；仅「擦音」一个词就让它搬出完整的国际音标，一起梳理哪些辅音最麻烦。他在后续帖子里说，Agent 最擅长的是掌握 100% 数据、能自己做实验、独立验证并逐步逼近目标的任务，这类任务他完全放心。670+ 赞。
