## AI 热点
1. **Claude Messages API: message threads enter public beta**: the API now caches the conversation server-side between turns, so you send only new messages plus the previous message ID and Claude starts responding sooner; in Claude Code, requests with 500K–1M tokens saw median time to first token drop ~35% and the median long-conversation request shrink from ~800 KB to 1.8 KB. Available on Claude Platform, AWS, Microsoft Foundry and Google Cloud at standard token rates (~8.1k likes). https://x.com/ClaudeDevs/status/2117332449382510884 | https://x.com/ClaudeDevs/status/2117332451231956997
> [zh] **Claude Messages API：消息线程进入公开测试**：API 在轮次之间把对话缓存在服务端，只需发送新消息和上一条消息 ID，Claude 更快开始回复；Claude Code 已接入，500K–1M token 的请求首 token 中位延迟约降 35%，长对话中位请求体从约 800 KB 降到 1.8 KB。Claude Platform、AWS、Microsoft Foundry、Google Cloud 均可用，按标准 token 计价（约 8.1k 赞）。
2. **OpenAI built Pando, a new Git backend for its monorepo**: handles more pushes and fetches without changing how engineers and agents use Git; push latency down ~80%, now serving nearly a petabyte of Git data a day, so Git capacity can grow with agent usage; fixes (e.g. cleanup after interrupted packfile downloads) were contributed upstream. Greg Brockman says they chose “the hard road of continuing to use Git” and are considering offering it externally. https://x.com/OpenAIDevs/status/2117408792346509663 | https://x.com/gdb/status/2117435285021810921 | https://openai.com/index/scaling-git-at-openai/
> [zh] **OpenAI 自研单仓 Git 后端 Pando**：在不改变工程师和 Agent 使用 Git 方式的前提下扛住更多 push / fetch；push 延迟降约 80%，每天服务近 1 PB Git 数据，Git 容量可随 Agent 用量增长；部分修复（如中断的 packfile 下载后的清理）已回馈上游。Greg Brockman 称他们走了「继续用 Git 的难路」，并在考虑对外提供。
3. **宝玉解读「权重空间编程」：GPT-6 Astra 不训练直接改权重，Qwen3.5-0.8B 数学从 7.9% 到 48.1%**：MIT CSAIL 四位研究者 11/2 博客：只动 0.016% 权重，删掉第 15、19 层里导致重复循环的方向（需允许拿练习题试跑 50 次）；Astra 还能只看权重认出四个游戏网络、一次改 3.5% 权重让仿真小车 1,024 次全成功、从零写出打砖块网络得分 517.4。换成少循环的 Gemma 3 270M 无提升，作者结论是改权重能去障碍、加不出原本没有的能力；结果尚无独立复现。https://x.com/dotey/status/2117408133773705525 | https://rikiyat.github.io/blog/weight-space-programming/
> [en] **Baoyu on “weight-space programming”: GPT-6 Astra edits weights without training, lifting Qwen3.5-0.8B MATH from 7.9% to 48.1%**: an MIT CSAIL blog (Nov 2) reports touching just 0.016% of weights by deleting a loop-causing direction in layers 15 and 19 (with 50 practice-set trials allowed); Astra also identified four game networks from weights alone, fixed a failing sim car with one 3.5% edit (1,024/1,024 successes) and wrote a Breakout net from scratch scoring 517.4. No gain on the rarely-looping Gemma 3 270M—the authors say edits remove blockers but cannot add missing ability; not yet independently reproduced.
4. **Addy Osmani: “Critical thinking when agents do the work” (~19k bookmarks)**: a fan of agentic workflows argues that as models improve, fewer outputs are obviously wrong—most are well-written and mostly correct but “won't demand a second look”—and the space between question and answer where we used to think is now seconds long; “even if you are running many agents at a time, you still only have one pair of eyes.” https://x.com/addyosmani/status/2117512471930167377
> [zh] **Addy Osmani：《当 Agent 替你干活时的批判性思维》（约 1.9 万收藏）**：作为 Agent 工作流的拥护者，他指出模型越强，明显错误越少——多数输出写得好、基本正确，却「不会逼你再看一眼」；过去在提问与答案之间进行的思考，如今只剩几秒；「就算同时跑很多 Agent，你也只有一双眼睛。」

## 有趣用法和干货
1. **poteto: adversarial reviews are mostly a waste of tokens—spend them on empirical + formal verification**: she has updated pstack to use the interrogate skill less and may drop it; abstract code review agents “tend to just get lost in the nitpicks and yagnis” (~9.7k likes / 5.9k bookmarks). https://x.com/poteto/status/2117437607940681849
> [zh] **poteto：对抗式审查多半浪费 token，不如花在实证 + 形式化验证上**：她已让 pstack 少用 interrogate skill，之后可能彻底去掉；抽象的代码审查里，Agent「容易迷失在吹毛求疵和 YAGNI 里」（约 9.7k 赞 / 5.9k 收藏）。
2. **Vox: don’t say “make it faster”—give Claude Code a profile-first perf review prompt**: run a profile, list the 5 slowest spots and their time, then match each to one case only: caches hiding a slow design (don’t add more), hot loops on hash tables → flat arrays/indices, objects read for one or two fields → AoS → SoA, sequential independent awaits → parallel, otherwise data-oriented rewrite; report time, case, file/lines and expected speedup before changing anything. https://x.com/Voxyz_ai/status/2117342228767281487
> [zh] **Vox：别只说「让它更快」，给 Claude Code 一段先 profile 的性能审查提示词**：先跑 profile 找出最慢的 5 处及耗时，每处只套一种情形：用缓存掩盖慢设计（别再加缓存）、热循环频繁查哈希表 → 平铺数组 / 下标、对象多但每次只读一两个字段 → AoS 转 SoA、互不依赖的 await 串行 → 并行，都不符合就按面向数据设计重写；改动前先报告耗时、情形、文件行号和预期提速。

> [zh] **Matt Pocock：有研究者专门写论文评估他的 /retro skill**：论文《How Do Coding-Agent Harnesses Self-Evolve?》用 Claude Code（Opus 5.5）跑 SWE-bench Verified，收集 125 条 /retro 建议并测试落地效果；7 次有效测试里只有 2 项彻底消除目标问题——相信「自我进化 skill」前值得一看。
