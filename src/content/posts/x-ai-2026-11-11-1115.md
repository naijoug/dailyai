## 有趣用法和干货
1. **Matt Pocock's "Home Repo" for working with agents across many repos**: keep one repo that holds all your skills, steering files and wiki, run your agent there, and put pointers to the other repos in its AGENTS.md (e.g. "For skills, clone mattpocock/skills to ~/repos/skills"). That gives one place for tooling, one spot to run every agent, and an easy way to make sweeping changes across repos. In replies: repo-specific details stay in each repo with only navigation pointers at home, cross-repo issues live in the home repo, he uses worktrees inside each clone, and on a team the home repo is shared and everyone runs their agents there. https://x.com/mattpocockuk/status/2120260969750540327
> [zh] **Matt Pocock 的「Home Repo」：一个仓库统管多仓库 Agent 开发**：单独建一个「家」仓库，放所有 skill、引导文件和 wiki，Agent 在这里运行，AGENTS.md 里写上其他仓库的指引（如「skills 就把 mattpocock/skills 克隆到 ~/repos/skills」）。好处是工具集中在一处、所有 Agent 从同一处启动、跨仓库大改也方便。他在回复里补充：各仓库自己的细节留在各自仓库，家仓库只放导航指引；跨仓库的 issue 放在家仓库；每个克隆里用 worktree；团队场景下家仓库归团队共有，大家都在里面跑 Agent。
2. **宵明解读 Shopify：30 名工程师 12 周用 Agent 重写 300 多页的商家 App，功夫全花在验证上**：从 React Native 改成 Swift 和 Kotlin 双原生。动手前先给 Agent 搭环境：统一两端结构的内部架构 Reflex、不开模拟器就能跑业务逻辑的命令行工具、偏离规范就报错的仓库规则，让多数页面在终端里就能做确定性检查。写规格很快过时，改为用内部工具 Helix 读取旧版 App，把迁移拆成便于审查的小步骤并与原应用对照验收。两人一组、每人同时指挥多个 Agent，PR 必须人审但先由 Agent 按架构规范互查；每天把审查意见写回技能说明和架构文档，崩溃监测每 15 分钟跑一次，Slack 里的 Agent 可复现问题并直接提修复 PR。Shopify 自报 Android 启动中位数 1.71→0.87 秒、安装包 80.4→47.6MB。https://x.com/shao__meng/status/2120335490524365241 | https://shopify.engineering/shopify-app-rebuild | https://x.com/ShopifyEng/status/2120194571313279263
> [en] **shao__meng on Shopify: 30 engineers used agents to rebuild a 300+ screen merchant app in 12 weeks, and the effort went into verification**: moving from React Native to native Swift and Kotlin, they first built an agent-ready setup — the Reflex architecture keeping both platforms aligned, a CLI to run business logic without a simulator, and repo rules that fail on deviations — so most screens get deterministic checks in the terminal. Specs went stale fast, so the internal Helix tool reads the old app, splits the migration into reviewable steps and checks new screens against the original. Engineers work in pairs, each steering several agents; every PR gets human review, but agents cross-check against architecture rules first; review notes are written back into skills and architecture docs daily, crash monitoring runs every 15 minutes, and a Slack agent reproduces issues and opens fix PRs. Shopify reports Android median startup 1.71→0.87 s and install size 80.4→47.6 MB.
3. **宝玉：Claude Artifacts 说明软件设计的重心变成「让人更好地验收」**：他认为软件正在从「给人用」变成「给 Agent 用、人审查微调」，并举了三点：多人协作变成人和 Agent 协作，能看到 Agent 正在做的操作和全部历史，在设计稿上留评论让它改、它改完会回复你；直接操作变成标记加评论，比如在 Claude Motion 里大致框一段时间线，说一句「把这段里静音的部分剪掉」，不用再放大波形手动打点；人主导变成 Agent 先采访人，在 Claude Design、Claude Slides 里只需描述模糊想法、回答几道选择题，它就给出几个版本让你挑。https://x.com/dotey/status/2120345202804101583
> [en] **Baoyu: Claude Artifacts shows software design shifting toward making human review easy**: he argues software is moving from "for people to operate" to "for agents to operate, with people reviewing and tweaking," with three examples: human-human collaboration becomes human-agent collaboration, where you see what the agent is doing and its full history and leave comments on a design that it answers after fixing; direct manipulation becomes mark-and-comment, like roughly selecting a span in Claude Motion and saying "cut the silent parts" instead of zooming into waveforms; and human-led work becomes the agent interviewing you, as in Claude Design or Claude Slides, where a vague idea plus a few multiple-choice answers yields several versions to pick from.
