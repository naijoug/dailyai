## 有趣用法和干货
1. **Lauren Tan 在 AIE CODE 讲 Grok Bot 团队怎样「把 slop 变成黄金」：上月 11000 个 PR 上生产，回滚约 0.5%**：MaiYangAI 做了中英字幕版并摘要。她把信任 Agent 的前提放在代码库上：好的 API、架构、类型系统和测试能让 Agent 默认做对；客户端框架 Dune 用依赖图分析器拦住主线程与渲染线程之间的违规导入；团队禁掉了 99% 的注释，因为 Agent 会在注释里替快速补丁找理由；每次纠正 Agent，都尽量变成一条可执行的确定性检查，而不是在 agents.md 里再加一行；代码评审更多看视频、截图和验证产物，TLA+、Lean 和 UI 测试已经找到过 bug。结果是大约每天发一个稳定版，启动、打字、切换聊天都比上线时更快。https://x.com/MaiYangAI/status/2120735641856348407 | https://x.com/FinanceYF5/status/2120785821209137440
> [en] **Lauren Tan at AIE CODE on how the Grok Bot team "turns slop into gold": 11,000 PRs to production last month, ~0.5% reverted**: MaiYangAI subtitled the talk in Chinese and English and summarized it. She grounds trust in agents in the codebase: good APIs, architecture, types and tests make agents do the right thing by default; in the Dune client framework a dependency-graph analyzer blocks illegal imports between the main and render threads; the team banned 99% of comments because agents use them to justify quick patches; every correction to an agent becomes, where possible, an executable deterministic check instead of another line in agents.md; review leans on videos, screenshots and verification artifacts, and TLA+, Lean and UI tests have already caught bugs. The result is roughly one stable release a day, with startup, typing and chat switching all faster than at launch.
2. **微软开源 TokenEconomizer：从跑过的会话里学经验，给编程 Agent 省 18%–31% 的钱**：GitHub_Daily 推荐。不换模型、不改 Agent，三招：把反复踩的坑和仓库常识（比如这里要用 `python -m pytest`）总结成一句话的 micro-skill，三次会话确认后在开场告诉 Agent；连续几次会话都没用过的工具下次不加载；Agent 同一个报错原地打转时请裁判模型判断，确认卡住就提醒换思路。UC Berkeley 和微软研究院在 SWE-Bench 277 个任务上测了 5 种 Agent 和模型组合，平均成本降 18.4%–30.9%，30 个仓库×组合全部更省，5 种里 4 种通过率略升。支持 Claude Code、Codex、GitHub Copilot CLI 和 Pi，学到的东西只存本机。https://x.com/GitHub_Daily/status/2120818905942007846 | https://github.com/microsoft/TokenEconomizer
> [en] **Microsoft open-sources TokenEconomizer: learn from past sessions and cut coding-agent costs 18–31%**: recommended by GitHub_Daily. It changes neither the model nor the agent, and uses three mechanisms: repeated pitfalls and repo facts (say, `python -m pytest` here) become one-line micro-skills, stated at session start once three sessions confirm them; tools unused for several sessions stop being loaded; and when the agent loops on the same error, a judge model checks and nudges it to try another way. UC Berkeley and Microsoft Research tested 5 agent–model combos on 277 SWE-Bench tasks: mean cost fell 18.4–30.9%, every one of 30 repo × combo cells got cheaper, and Pass@1 rose slightly in 4 of 5. It supports Claude Code, Codex, GitHub Copilot CLI and Pi, and keeps what it learns on your machine.
3. **《Jev 工程学：为 coding agent 而作》中文译本**：GitHub_Daily 推荐。笔记综合自 TypeSafe 创始人 Diogo Almeida 的设计笔记，认为编程 Agent 的差距不在「模型加工具」的循环本身，而在每一轮喂给模型的东西；从「如果模型没有 KV cache，Agent 该怎么设计」切入，拆出现有 Agent 默认继承的 6 个设计选择，讲到模型路由为什么省不下钱、上下文压缩为什么盲目、子 Agent 为什么很少被触发，还专门算了 Token 账。仓库完整保留原结构和 7 张插图，附作者原始笔记。https://x.com/GitHub_Daily/status/2120781150507631016 | https://github.com/yibie/jev-engineering-zh
> [en] **A Chinese translation of "Jev Engineering: written for coding agents"**: recommended by GitHub_Daily. Drawn from design notes by TypeSafe founder Diogo Almeida, it argues the gap between coding agents isn't in the model-plus-tools loop but in what gets fed to the model each turn. Starting from "how would you design a coding agent if models had no KV cache?", it pulls out six design choices today's agents inherit by default, and covers why model routing doesn't save money, why context compaction is blind, why subagents rarely trigger, plus a section doing the token math. The repo keeps the original structure and all 7 illustrations, with the author's raw notes alongside.
