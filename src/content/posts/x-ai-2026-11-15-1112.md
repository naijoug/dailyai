## AI 热点
1. **Claude Code ships experimental Code Mode**: instead of requesting Bash/Read/Edit one at a time, Claude can write a JavaScript snippet that runs several tool calls in one step (including in parallel and chaining results) and returns only the output it needs. Official docs require Claude Code v2.1.323 or later, a Claude subscription or Console account (not Bedrock, Vertex, Foundry, or a gateway), and the native terminal `claude` binary — not `-p`, the Agent SDK, the VS Code panel, Desktop, or cloud sessions — with models Opus 5.5, Sonnet 5.5, Haiku 5.5, or Fable 5.2. Enable it with `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude` or the same key in `~/.claude/settings.json` (user settings only; a cloned repo cannot turn it on). The first session asks for confirmation and then shows “Code Mode (experimental) is on”; inspect the generated JS with Ctrl+O. Docs warn that a Code Mode session can be resumed only in the terminal with Code Mode still on; auto mode’s classifier reviews the code, not each tool call; foreground code stops after ten minutes; background code can run up to two hours in auto/`bypassPermissions`; Remote Control, Claude in Chrome, computer use, agent teams, and some telemetry/API-key-helper setups are incompatible. No official Anthropic or ClaudeDevs post was found in this window; the docs page is the primary source. https://x.com/pggalaviz/status/2121652838447169783 | https://code.claude.com/docs/en/code-mode
> [zh] **Claude Code 上线实验性 Code Mode**：以前要一次次单独请求 Bash/Read/Edit，现在 Claude 可以写一段 JavaScript，在同一步里跑多次工具调用（包括并行，以及把上一次的结果接到下一次），只把需要的输出返回来。官方文档要求 Claude Code v2.1.323 或更高，需要 Claude 订阅或 Console 账号（不能用 Bedrock、Vertex、Foundry 或网关），而且只能用终端里的原生 `claude` 二进制——不能用 `-p`、Agent SDK、VS Code 面板、桌面版或云端会话——模型限 Opus 5.5、Sonnet 5.5、Haiku 5.5 或 Fable 5.2。开启方式是 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude`，或在 `~/.claude/settings.json` 里写同一项（只认用户设置，克隆来的仓库开不了）。第一次会话会先征求确认，然后显示 “Code Mode (experimental) is on”；可用 Ctrl+O 查看生成的 JS。文档提醒：Code Mode 会话只能在终端里、并且 Code Mode 仍开启时恢复；auto mode 的分类器审查的是这段代码，而不是每一次工具调用；前台代码 10 分钟后会停；后台代码在 auto/`bypassPermissions` 下最多可跑两小时；Remote Control、Claude in Chrome、computer use、agent teams，以及部分遥测/API-key-helper 组合不兼容。本窗口内没有找到 Anthropic 或 ClaudeDevs 的官方帖，主要依据是文档页。
2. **Obsidian Skills now has seven agent skills, including Headless**: CEO Steph Ango (@kepano) said the pack now has seven skills that teach agents how to operate Obsidian vaults and wikis: `obsidian-markdown` (Obsidian Flavored Markdown with wikilinks, embeds, callouts and properties), `obsidian-bases` (`.base` files with views, filters, formulas and summaries), `json-canvas`, `obsidian-cli` (vault and CLI work, including plugin and theme development), `obsidian-headless` (sync and publish from the command line with Obsidian Headless, without the desktop app), `defuddle` (extract clean markdown from web pages to save tokens), and `knap` (render Markdown templates from JSON or CSV, including batch generation). In a follow-up he said you do not need the Obsidian app to use the skills, and that with the CLI skill, wikilinks can be renamed automatically across the vault. The official repo README says the skills follow the Agent Skills spec and work with Claude Code, Codex and OpenCode; Claude Code install is `claude plugin marketplace add obsidianmd/obsidian-skills` then `claude plugin install obsidian@obsidian-skills`. Cursor install is via the Cursor Marketplace; `npx skills add https://github.com/obsidianmd/obsidian-skills` also works. https://x.com/kepano/status/2121671411119059034 | https://x.com/kepano/status/2121671835066786169 | https://github.com/obsidianmd/obsidian-skills

4. **Most SaaS should become an MCP server**: @nicbstme argues that many AI startups are “reselling tokens from the big labs at low to negative gross margins” by building their own chat UIs, agents and workflows. The alternative: a vertical SaaS company should become “the best MCP server” for its domain and let ChatGPT, Claude or Copilot handle conversation, reasoning and orchestration, while the customer pays for the tokens. An HR example lists tools to expose: benchmark salaries against proprietary market data; run compensation reviews and pay-equity calculations; model raises against a department budget; recommend promotions from company policy; update compensation in the HRIS; and manage approvals, permissions and audit trails. The SaaS firm keeps proprietary data, integrations, business logic, permissions, compliance and the system of record, still charges a subscription, and is “no longer paying to generate every answer.” The closing line: “The next generation of SaaS might not have much of a UI at all. Just an incredibly good MCP server.” In a reply the author agreed customers still want an end-to-end experience and someone to blame, and that not every enterprise will “vibe code an alternative.” This is a personal strategy argument, not a product launch. https://x.com/nicbstme/status/2121690979904446885
> [zh] **大多数 SaaS 都应该变成一个 MCP 服务器**：@nicbstme 认为，很多 AI 创业公司是在「以很低甚至为负的毛利率转售大实验室的 token」，自己去做聊天界面、Agent 和工作流。另一种做法是：垂直 SaaS 公司应该成为自己领域里「最好的 MCP 服务器」，把对话、推理和编排交给 ChatGPT、Claude 或 Copilot，token 则由客户自己付。他举的 HR 例子包括对外提供这些工具：用自有市场数据做薪资对标、做薪酬回顾和薪酬公平计算、按部门预算模拟加薪、按公司政策建议晋升、在 HRIS 里更新薪酬，以及管理审批、权限和审计轨迹。SaaS 公司仍保有专有数据、集成、业务逻辑、权限、合规和系统记录，也还收订阅费，只是「不再为生成每一个答案付钱」。结尾写：「下一代 SaaS 可能没有多少界面，只是一个非常好的 MCP 服务器。」他在回复里也同意，客户仍然想要端到端的体验和能问责的对象，而且不是每家企业都会「vibe code 出一个替代品」。这是个人策略讨论，不是产品发布。

## 有趣用法和干货
1. **Preview on your phone: Tailscale Serve plus one AGENTS.md/CLAUDE.md line**: @Voxyz_ai posted a four-step workflow. Install Tailscale on the computer and the phone with the same account (it is free). Open the project in Claude Code or Codex. Ask the agent to run the project and send a preview link. Then add a standing instruction so the link opens on the phone, saved to AGENTS.md or CLAUDE.md: “Any time you give me a link to something running on this computer (a preview, a review page, a dashboard), give me a Tailscale link, never localhost. I work across several computers and my phone. Publish it with tailscale serve, open the link yourself to check it works, then send it.” Replies in the thread described this as a replacement for ngrok and noted that a real phone catches layout issues (for example the keyboard covering a submit button) that desktop devtools miss. The post does not document Tailscale Serve auth, funnel ACLs, or what happens if Serve is not already set up. https://x.com/Voxyz_ai/status/2121702208546967753
> [zh] **在手机上预览：Tailscale Serve 再加一行 AGENTS.md/CLAUDE.md**：@Voxyz_ai 发了一个四步工作流。在电脑和手机上用同一个账号安装 Tailscale（免费）。用 Claude Code 或 Codex 打开项目。让 Agent 跑起来并发来预览链接。然后再加一条常驻指令，让链接能在手机上打开，写进 AGENTS.md 或 CLAUDE.md：「Any time you give me a link to something running on this computer (a preview, a review page, a dashboard), give me a Tailscale link, never localhost. I work across several computers and my phone. Publish it with tailscale serve, open the link yourself to check it works, then send it。」线程里的回复把它说成 ngrok 的替代，并提到真机才能发现桌面开发者工具容易漏掉的布局问题，比如键盘挡住提交按钮。帖子没有写 Tailscale Serve 的鉴权、funnel ACL，以及 Serve 还没配好时会怎样。
2. **Addy Osmani: use Opus 5.5 at medium as the daily driver**: the Claude Code team member wrote that Opus 5.5 at medium is a great daily driver; if it struggles, raise the effort before switching models; otherwise Fable 5.2 is good for the genuinely hard stuff (big migrations, long unattended runs). He linked his official article (dated 9 Nov, not published today) which matches the tweet: start most work on Opus 5.5 at default effort `medium` — the default in Claude Code, and half the input and output token cost of Fable 5.2. Move down to Sonnet 5.5 for well-scoped everyday work and to Haiku 5.5 for high-volume classification, routing, extraction or side-task subagents; move up to Fable 5.2 for the hardest technical projects, when Opus 5.5 at `high` still falls short, or for long unattended runs. Before changing models, try effort; past `high`, one more effort level can cost as much as a bigger model. In a later reply he said medium is good enough that they set it as the default in Claude Code for Opus 5.5. https://x.com/addyosmani/status/2121732470118965298 | https://claude.dev/blog/which-claude-model-should-you-build-with/
> [zh] **Addy Osmani：日常用 Opus 5.5 的 medium 档就很好**：这位 Claude Code 团队成员写到，Opus 5.5 开 medium 是很好的日常主力；如果它吃力了，先提高 effort，再考虑换模型；真正难的活（大迁移、长时间无人值守）再用 Fable 5.2。他链到了自己的官方文章（日期是 11 月 9 日，不是今天发的），内容和推文一致：大多数工作从 Opus 5.5、默认 effort `medium` 开始——这也是 Claude Code 的默认设置，输入和输出 token 费用大约是 Fable 5.2 的一半。范围清楚的日常工作可以降到 Sonnet 5.5；高频分类、路由、抽取或给子 Agent 的旁路任务可以用 Haiku 5.5；最难的技术项目、Opus 5.5 开到 `high` 仍不够，或需要长时间无人值守时，再升到 Fable 5.2。换模型之前先试 effort；过了 `high` 之后，再升一档 effort，费用可能已经相当于换一个更大的模型。他后来在回复里说，medium 已经够好，所以他们把 Opus 5.5 在 Claude Code 里的默认就设成了这一档。

4. **Voxyz: put two-way vs one-way doors into AGENTS.md**: a short copy-paste policy: “Walk through two-way doors and show me after. Stop at one-way doors.” Two-way doors are reversible: code, branches, PRs, test data and dev infra. One-way doors are not: prod data, deploys to users, force-pushing a shared branch, deleting what you didn’t make, or a message sent to another person. Additional rules: if the user’s answer would be a rubber stamp, don’t ask; if running something could answer the question, run it instead; save questions for taste and product calls only the user can make; ask one at a time, with a recommendation, using the built-in question tool. https://x.com/Voxyz_ai/status/2121672008421568810
> [zh] **Voxyz：把双向门和单向门写进 AGENTS.md**：这是一段可直接粘贴的策略：「Walk through two-way doors and show me after. Stop at one-way doors。」双向门是可逆的：代码、分支、PR、测试数据和开发环境。单向门不可逆：生产数据、向用户发布、对共享分支强制推送、删除不是自己建的东西，以及已经发给别人的消息。还有几条：如果用户的回答只会是走过场，就不要问；如果跑一下就能得到答案，就先跑；把问题留给只有用户能做的品味和产品判断；一次只问一个，并给出建议，使用内置的提问工具。
