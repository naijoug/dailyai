## 新产品
1. **Mirasim**: a multiplayer coding-agent workspace whose pitch is “Build anything with anyone”: several people can steer the same agent session with every message signed by its sender, and a team can share a space, API keys or credit, while agents run on your own machine, a hosted team space or an SSH server. It drives Claude Code, Codex, Kimi Code, DeepSeek Harness, OpenCode, Qwen Code, Pi and Antigravity, runs parallel sessions in separate git worktrees, and stores chats, voice and sessions as plain files under ~/.mirasim/; it is not open source, and its own comparison page positions it as the team option next to the free, MIT-licensed T3 Code. https://mirasim.ai/ https://mirasim.ai/writing/mirasim-vs-t3-code
> [zh] **Mirasim**：主打「Build anything with anyone」的多人协作编程 Agent 工作区：多人可以一起指挥同一个 Agent 会话，每条消息都标明发送者，团队能共享空间、API key 或额度，而 Agent 运行在你自己的电脑、托管的团队空间或 SSH 服务器上。它能驱动 Claude Code、Codex、Kimi Code、DeepSeek Harness、OpenCode、Qwen Code、Pi 和 Antigravity，在各自独立的 git worktree 里并行跑会话，并把聊天、语音和会话以纯文件存在 ~/.mirasim/ 下；它不开源，官方对比页把自己定位成免费、MIT 许可的 T3 Code 旁边的团队版选择。
2. **Carry**: a Chrome extension that automatically saves your ChatGPT, Claude, Gemini and Grok conversations, projects and files as Markdown in a local folder you choose (Obsidian vaults work), keeps them updated as you keep chatting, searches across all of them by app, date and project, and can reopen any saved chat in another AI with the transcript attached. The maker says it is local-only and never uploads chats, offers 14 days free, and keeps your files if you uninstall; a Show HN thread drew 27 points. https://carry.md/ https://news.ycombinator.com/item?id=50637995
> [zh] **Carry**：一个 Chrome 扩展，把你在 ChatGPT、Claude、Gemini 和 Grok 里的对话、项目和文件自动存成 Markdown，放进你选的本地文件夹（可直接用 Obsidian 库），你继续聊就继续更新，还能按应用、日期和项目跨所有对话搜索，并把任意一条已存对话带着记录在另一个 AI 里重新打开。作者称它只在本地运行、不上传对话，提供 14 天免费试用，卸载后文件仍归你；Show HN 帖子拿到 27 分。
3. **Search for Agents (Cloudflare)**: one toggle in a Cloudflare zone that creates an AI Search instance, indexes the site’s content and exposes a search endpoint under the site’s own domain at /.well-known/search, returning Markdown results rather than generated answers. Every page advertises the endpoint through agent:* meta tags (or YAML front matter when Markdown for Agents is on), and it supports the new HTTP QUERY method (RFC 10008) as well as GET. It is available to all customers including Free with limits, and Cloudflare turned it on for its own developer docs, where OpenCode found and used it to answer a question. https://developers.cloudflare.com/ai-search/how-to/search-for-agents/ https://blog.cloudflare.com/search-for-agents/
> [zh] **Search for Agents（Cloudflare）**：在 Cloudflare 的某个 zone 里打开一个开关，就会创建一个 AI Search 实例、为站点内容建索引，并在站点自己的域名下的 /.well-known/search 暴露搜索端点，返回的是 Markdown 检索结果而不是生成的答案。每个页面都会用 agent:* 元标签（开启 Markdown for Agents 时用 YAML 头）宣告该端点，除 GET 外还支持新的 HTTP QUERY 方法（RFC 10008）。所有客户可用（含有限额的免费版），Cloudflare 已在自家开发者文档上启用，OpenCode 在其中自己发现并用它回答了问题。
4. **Diagram Design**: an open-source skill from Cathryn Lavery that has your coding agent draw 52 types of diagrams (architecture, Sankey, heatmap, exploded axonometric, database schema and more) as a single self-contained HTML + SVG file that opens offline, then match them to your own site’s colors and fonts in about a minute. It can redraw draw.io, Mermaid and Excalidraw sources, installs with `npx skills add cathrynlavery/diagram-design` or as a plugin for Claude Code, Codex, Copilot, Pi and others, and the site says it hit #1 on GitHub Trending. https://diagramdesign.dev https://github.com/cathrynlavery/diagram-design
> [zh] **Diagram Design**：Cathryn Lavery 的开源 skill，让你的编程 Agent 画 52 种图（架构图、桑基图、热力图、爆炸轴测图、数据库结构等），输出成一个能离线打开的单文件 HTML + SVG，并在约一分钟内按你自己网站的配色和字体统一风格。它能重画 draw.io、Mermaid 和 Excalidraw 源文件，可用 `npx skills add cathrynlavery/diagram-design` 安装，或作为插件用于 Claude Code、Codex、Copilot、Pi 等；官网称它登上过 GitHub Trending 第一。

## 科技新闻
1. **1Password discloses a backend breach: customer names and emails were copied, vaults were not touched**: the company says that from November 19 it investigated an attacker who used an employee’s corporate GitHub account to read source code and push malicious code to backend services, which downloaded account records for a subset of customers: names and email addresses, identifiers, sign-in times, public keys, SRP parameters and tokens in emailed invitation and recovery links. Vault contents, the keys protecting them, the password and the Secret Key were not accessed; 1Password revoked the token, rotated credentials, and lengthened invitation and recovery codes from six digits to ten alphanumeric characters, and warns customers to watch for phishing. The post reached 1,200+ points on HN. https://1password.com/blog/update-on-nov-2026-security-incident https://news.ycombinator.com/item?id=50644817
> [zh] **1Password 披露后端遭入侵：客户姓名和邮箱被复制，保险库未受影响**：公司称自 11 月 19 日起调查一名攻击者，其利用一名员工的企业 GitHub 账号读取源码并向后端服务推送恶意代码，随后下载了一部分客户的账户记录：姓名和邮箱、标识符、登录时间、公钥、SRP 参数，以及邮件邀请和恢复链接中的令牌。保险库内容、保护它们的密钥、密码和 Secret Key 均未被访问；1Password 已吊销令牌、轮换凭据，并把邀请和恢复验证码从 6 位数字加长到 10 位字母数字，同时提醒客户防范钓鱼。该帖在 HN 上超过 1200 分。
2. **Google releases six “Cogentic” research papers, including algorithms for integer factoring and discrete logs**: the google-research repository lists papers produced by Cogentic dated November 25, among them “Unconditional Integer Factorization in Time L_N[1/3, O(1)]”, “Unconditional Deterministic Subexponential Integer Factoring and Quadratic Nonresidue Construction”, “Discrete Logarithms in Finite Fields of Fixed Characteristic in Sub-Quasi-Polynomial Time” and “Breaking the Square-Root Barrier for the Log-Rank Conjecture”. Commenters under Scott Aaronson’s post say the factoring results are theoretical, that the deterministic algorithm is slower than the average case of the number field sieve, and that nothing here breaks RSA, and that the papers were reportedly reviewed by human experts but do not come with Lean formalizations. https://github.com/google-research/google-research/tree/master/cogentic_research_papers https://news.ycombinator.com/item?id=50642086 https://scottaaronson.blog/?p=10379
> [zh] **谷歌发布六篇「Cogentic」研究论文，含整数分解和离散对数算法**：google-research 仓库列出了 11 月 25 日由 Cogentic 产出的论文，包括《Unconditional Integer Factorization in Time L_N[1/3, O(1)]》《Unconditional Deterministic Subexponential Integer Factoring and Quadratic Nonresidue Construction》《Discrete Logarithms in Finite Fields of Fixed Characteristic in Sub-Quasi-Polynomial Time》和《Breaking the Square-Root Barrier for the Log-Rank Conjecture》。Scott Aaronson 博文下的评论者称，这些分解结果偏理论，其中确定性算法比数域筛法的平均情况还慢，并不会破解 RSA；据称论文发布前经人类专家审阅，但没有附带 Lean 形式化。
3. **Anthropic researchers publish a much shorter Lean proof of the Generalized Riemann Hypothesis**: per 量子位, Luke Sernau and colleagues, working with Claude, cut the earlier 17.4-million-line Alpöge proof to a compact version of about 76,000 lines (readable version about 300,000), which builds in 1–2 hours on a 12-core, 24 GB machine instead of about 21 hours on a large AWS box. It uses no `sorry` and only the three standard Lean axioms, was cross-checked by Lean’s kernel, Comparator and several independent checkers, is released under Apache 2.0, and was shortened by unrolling definitions into a flat proof, simplifying across module boundaries and re-packaging; the repo notes it is machine-verified but not yet read end to end by mathematicians. https://github.com/lsernau/grh-lean https://news.ycombinator.com/item?id=50648050 https://www.qbitai.com/2026/11/512819.html
> [zh] **Anthropic 研究员发布短得多的广义黎曼猜想 Lean 证明**：据量子位报道，Luke Sernau 与同事借助 Claude，把此前 1740 万行的 Alpöge 证明压到约 7.6 万行的紧凑版（可读版约 30 万行），在 12 核 24 GB 的机器上 1–2 小时即可构建，而原版在大型 AWS 机器上要约 21 小时。它不含 `sorry`、只用 Lean 的三条标准公理，经 Lean 内核、Comparator 和多个独立检查器交叉验证，以 Apache 2.0 开源；精简方法是把定义展开成扁平证明、跨模块边界化简再重新封装；仓库说明称它只经过机器验证，还没有数学家完整通读。
4. **US chip-access curbs and anti-distillation are reportedly slowing Chinese AI labs**: The Information, via The Decoder, reports DeepSeek, Moonshot AI and Alibaba have been squeezed since September by limits on remote access to advanced Nvidia chips in foreign data centers and by effective anti-distillation measures from OpenAI and Anthropic. DeepSeek researchers reportedly estimated internally last month that their gap to top US models could grow from three to six months to nine if distillation disappears completely, and Moonshot cancelled a $150 million Nvidia Blackwell deal in Indonesia; firms are renting compute through non-Chinese third parties, leaning on domestic chips and investing more in their own reinforcement-learning data. https://the-decoder.com/us-chip-access-curbs-and-anti-distillation-measures-are-reportedly-already-slowing-chinese-ai-labs/
> [zh] **据报道，美国的芯片访问限制和反蒸馏措施已在拖慢中国 AI 实验室**：The Decoder 转述 The Information 的报道称，DeepSeek、月之暗面和阿里自 9 月起一方面受限于对境外数据中心先进英伟达芯片的远程访问限制，另一方面受 OpenAI 和 Anthropic 有效的反蒸馏措施挤压。据称 DeepSeek 研究人员上月内部估计，若蒸馏完全消失，与美国顶尖模型的差距可能从三到六个月扩大到九个月，月之暗面已取消在印尼价值 1.5 亿美元的英伟达 Blackwell 订单；各家正通过非中国第三方租算力、更多依赖国产芯片，并加大自有强化学习数据投入。
5. **JetBrains releases Mellum2.1 Instruct, a coding model that uses 45% fewer tokens by not thinking**: built for sub-agents, tool loops and chat, the mixture-of-experts model activates 2.5B of 12B parameters per token and doubles its predecessor’s SWE-bench Verified score from 20.2% to 40.4%, still behind Qwen3.5 9B at 49.8% but about 1.4x faster per request. In JetBrains’ agentic tests it averaged 5,600 tokens per task versus 10,100 for Mellum2.1 Thinking, though the Thinking variant stays better on competitive programming and math. It is Apache 2.0 on Hugging Face with a GGUF build and an MTP head that speeds generation up to 1.8x. https://thenewstack.io/jetbrains-mellum2-1-instruct-coding-model/
> [zh] **JetBrains 发布 Mellum2.1 Instruct：靠「不思考」少用 45% token 的编程模型**：这个专为子 Agent、工具循环和聊天设计的混合专家模型，每个 token 只激活 12B 参数中的 2.5B，SWE-bench Verified 从上代的 20.2% 翻倍到 40.4%，仍落后于 Qwen3.5 9B 的 49.8%，但单请求约快 1.4 倍。在 JetBrains 的 Agent 测试里，它平均每题 5600 个 token，而 Mellum2.1 Thinking 为 10100 个，不过在竞赛编程和数学上 Thinking 版仍更好。模型以 Apache 2.0 发布在 Hugging Face，带 GGUF 版本和最多提速 1.8 倍的 MTP 头。
