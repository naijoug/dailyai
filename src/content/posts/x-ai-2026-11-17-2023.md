## 有趣用法和干货
1. **Matt Pocock’s prompt for assessing a new technology with an agent**: research what it does; find the gnarliest problem in your app it might help with; build a proof of concept in a draft PR; fully verify it; then grade API nuance (more is worse, since agents do better with fewer choices), type safety, testability, added cyclomatic complexity, docs quality and deployment changes, and give a recommendation. His example was the XState v6 beta (about 480 bookmarks). A follow-up idea: a `/constrain` tool that turns harsh lint rules into an extremely constrained version of your stack, e.g. React with all state in Zustand/useReducer. https://x.com/mattpocockuk/status/2122618527840354327
> [zh] **Matt Pocock：让 Agent 评估一项新技术的提示词**：先研究它做什么、解决什么问题；在你的应用里找它最可能帮上忙的最棘手问题；在草稿 PR 里做概念验证；完整验证结果；再按 API 的细节复杂度（越多越差，Agent 选择越少表现越好）、类型安全、可测试性、新增圈复杂度、文档质量和部署改动打分，最后给出建议。他的例子是 XState v6 beta（约 480 收藏）。后续他还设想做个 `/constrain`：用严格的 lint 规则把常用技术栈收窄成极简版本，比如允许用 React，但状态只能放在 Zustand/useReducer 里。
2. **Arpit Bhayani: pass the remaining deadline to every step of a multi-step agent**: instead of a fresh timeout per step, hand each downstream call the remaining budget. A timeout only stops the caller waiting, not the work: `Promise.race()` doesn’t stop the loser, Go context is cooperative, asyncio `to_thread()` isn’t force-stopped, and Rust timeouts only drop the awaiting handle. Separate “deadline passed,” “cancel requested” and “work stopped”; use an idempotency key bound to the request; and mind capacity: at 100 req/s with 30s of work and a 1s timeout, letting work run on means ~3,000 live operations instead of ~100. https://x.com/arpit_bhayani/status/2122534732730957877
> [zh] **Arpit Bhayani：多步 Agent 要把剩余截止时间传给每一步**：不要每一步都重新给一个超时，而是把剩余预算传给每个下游调用。超时只是让调用方不再等待，并不会停止工作：JavaScript 的 `Promise.race()` 不会停掉落败的 Promise，Go 的 context 需要函数主动配合，Python asyncio 的 `to_thread()` 不会被强制终止，Rust 的超时只丢弃正在等待的句柄。要区分「截止时间已过」「已请求取消」「工作真正停止」三件事；用绑定原始请求参数、在服务端原子校验的幂等键；还要算容量：每秒 100 个请求、每个工作 30 秒、调用方 1 秒超时，如果超时后工作继续跑，同时在跑的操作约 3,000 个，而不是约 100 个。

> [en] **GitHub Daily: Google Labs open-sources skills for Stitch so agents stop making “purple gradient” UIs**: installed in Claude Code, Codex, Cursor or Gemini CLI, they call Stitch to produce designs: generate a new screen from one sentence, edit an existing page, or produce several versions at once (e.g. “three dark-mode versions of the homepage”).
